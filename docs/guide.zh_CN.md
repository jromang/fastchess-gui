# fastchess-gui 用户指南

本指南介绍 fastchess-gui 的每个页面、每项设置和每个文件。[README](../README.md) 说明这个程序是什么、从哪里下载以及如何构建。在程序中，F1 会在页面旁打开本指南，定位到鼠标下方内容所属的章节，并使用界面的语言（见[程序内的帮助](#程序内的帮助)）。

## 快速入门
<!-- en: quick-start 92353f2c -->

### 第一个锦标赛
<!-- en: your-first-tournament 75e9a891 -->

1. **引擎**：在左侧的导航栏中点击*引擎*，然后点击*添加…* 并选择一个引擎的程序（UCI 或 WinBoard 可执行文件）：程序会启动它一次，读取它的名称和选项。*导入…* > *引擎列表…* 导入其他程序（cutechess、Banksia、Arena、ChessGUI）的引擎，*导入…* > *某个文件夹中的所有引擎…* 导入一个文件夹中的所有程序。*检查*可以判断引擎是否正常工作。
2. **新建锦标赛**：*锦标赛* > *新建锦标赛*。在*格式*的列表中选择一种（*循环赛*、*车轮战*等），再选择一个*时限*（初次尝试可选 *10+0.1*），其他各行保持不变。
3. **参赛者**：在参赛者旁边的*引擎库*中双击引擎，或者选中多个引擎后按 Enter。
4. **开始**：锦标赛在它的工作区中打开：*概览*显示排名和剩余时间，*实时*显示正在进行的对局。

设置右侧的摘要会说明将下多少局、需要多长时间，以及哪里会出问题（找不到程序、线程过多、缺少开局库），每个问题都附有一个修复它的按钮。

### 测试引擎的新版本
<!-- en: testing-a-new-version-of-an-engine 300dc828 -->

1. 将两个版本都添加到引擎库。
2. *新建锦标赛*，*格式*：*SPRT 提升 [0, 3]*（新版本有没有提升？）或 *SPRT 无退步 [-5, 0]*（新版本是否不比旧版本弱？）。
3. 选择新版本作为 **A**、旧版本作为 **B**，选择一个较短的时限（*10+0.1*），并在*开局*中选择一个由均衡局面组成的开局库（EPD），然后点击**开始**。

一旦 SPRT 得出结论，比赛会自行停止：接受 H1（按所设的边界，A 更强）或接受 H0（A 并不更强）。*概览*随着对局的进行显示 Elo、LLR 及其边界。设置会被保留：下次选择下一个版本作为 A 并点击**开始**即可，或者在已结束的比赛上点击*重新开始，使用…*。

## 窗口
<!-- en: the-window 3a5230d4 -->

### 页面
<!-- en: the-pages b13b4de2 -->

左侧的导航栏通向八个页面：

| 页面 | 内容 |
|---|---|
| 锦标赛 | 主页：正在进行的和需要处理的锦标赛、队列、最近结束的锦标赛、配置文件夹中的所有锦标赛、*新建锦标赛* |
| 引擎 | 引擎库：选项、检查、分组、参考 Elo、导入其他程序的引擎列表 |
| 开局库 | 开局库的列表，以及每个开局库中的开局及其存在的问题 |
| 棋盘 | 来自任何地方的对局或局面，由引擎库中的引擎分析 |
| 测试集 | 测试集（STS、WAC、ERET 等）：让引擎解 EPD 文件中的局面 |
| 等级分 | 基于所有锦标赛的所有对局的一份等级分榜 |
| 日志 | fastchess 自身的输出和程序的消息，以及*报告问题…* |
| 设置 | 语言、主题、界面大小、通知、棋盘外观、配置文件夹和锦标赛文件夹、远程机器、lichess 令牌、版本、窗口的绘制方式 |

### 程序内的帮助
<!-- en: help-in-the-program 351be20d -->

- **工具提示**：将鼠标停在某个控件上，即可看到它的作用。如果本指南对某个控件有更多说明，它的工具提示最后一行是 *F1：指南中有更多说明*。
- **F1** 在页面右侧的面板中打开本指南，定位到鼠标下方内容所属的章节（设置中的一行、主页上的一张卡片、一个标签页、排名中的一列）；鼠标下方没有内容时，定位到最后点击的面板所属的章节，否则定位到当前页面的章节。页面标题旁的圆形 **?** 打开该页面的章节。再按一次 F1，或在面板中按 Esc，即可关闭它。
- **指南面板**显示一个章节及其子章节，旁边的页面照常工作：可以一边阅读说明，一边修改设置。面板顶部有*后退*和*前进*（也可用 Alt+Left 和 Alt+Right，或鼠标的侧键）、*目录*（所有章节）、搜索框（在面板中按 Ctrl+F）以及*在浏览器中打开*（GitHub 上的本指南，对应正在运行的版本）。搜索会找出输入的每个词，不分先后顺序，不区分大小写和重音符号；标题中的匹配排在前面，匹配处会高亮显示。指向其他章节的链接在面板中打开，指向网页的链接在浏览器中打开，代码块带有*复制*按钮。拖动面板的左边缘可以加宽它，宽度会被保留。
- **语言**：本指南内置于程序中，提供界面的所有语言，并与正在运行的版本保持一致；不会从网络获取任何内容。如果某个章节的译文缺失或比英文原文旧，该章节以英文显示，并有一行文字说明这一点。发布压缩包中也包含本指南（`guide.md`，以及每种译文的 `guide.<language>.md`）。
- **Ctrl+K**，即命令面板，可以按标题查找指南的章节（*指南：…*），*在指南中搜索“…”* 则在指南中搜索输入的内容。
- **消息**：程序报告的问题会指明相关的引擎、文件或资源，并就地提供修复方法；问题旁的 **?** 打开它在[故障排除](#故障排除)中的条目。
- **开始使用**：在第一个锦标赛开始之前，主页会显示[快速入门](#快速入门)的各个步骤，每一步都有对应的按钮，完成后打勾；*隐藏*可以收起它们。
- 程序没有按预期工作时，请[报告问题](#报告问题)。

### 命令面板
<!-- en: the-command-palette 725e7934 -->

**Ctrl+K** 打开命令面板：其中有各个页面和标签页、引擎库中的引擎（打开其信息卡）、开局库、主页上的锦标赛、指南的章节，以及当前可执行的操作（*暂停*、*继续*、*全部暂停*、*停止*、*开始*、*加入队列*、*重新开始 …，使用…*、*导入…* 中的各项、*检查尚未检查的*、*导出给等级分列表…*、*复制*排名、*复制版本号*、*报告问题…*、棋盘颜色和棋子样式、开启或关闭走棋声音等）。不区分大小写，输入的字母也不必相邻（“rl”可以找到 *Rating list*）；以这些字母开头的名称，或其中有某个词以它们开头的名称，排在前面。上、下方向键选择，Enter 执行，Esc 关闭；正在文本框中输入时，Ctrl+K 不起作用。

### 语言、主题和大小
<!-- en: language-theme-and-size 954fe416 -->

界面提供英语、法语、德语、西班牙语、意大利语、巴西葡萄牙语、俄语和简体中文。启动时，界面使用系统的第一首选语言（没有该语言的译文时使用英语）；也可以在**设置**中指定语言。中文使用系统字体：Windows 上为 Microsoft YaHei（微软雅黑），Linux 上为 Noto Sans CJK 或 WenQuanYi（文泉驿）。主题默认为浅色，除非在**设置**中选择了深色或跟随系统。

西班牙语、意大利语、葡萄牙语、俄语和中文的译文是新加入的：欢迎使用这些语言的棋手提出修改意见。界面的译文是 `gui/i18n` 中普通的 `.po` 文件，Poedit 等工具可以打开；本指南的译文是 `docs/guide.<language>.md`。

无论窗口多大，页面都会占满整个窗口：“实时”标签页中的棋盘随窗口放大，新建锦标赛的表单在宽窗口中分为两栏，“引擎”“开局库”和“等级分”页面的列表可以拖动其右边缘加宽。所有内容（文字、按钮、棋盘）还可以整体放大或缩小，范围为 80% 到 250%：**设置** > 界面大小，或 Ctrl + 鼠标滚轮、Ctrl + 和 Ctrl -，Ctrl 0 恢复到 100%。F11 切换全屏。

*实时*标签页和*锦标赛*按钮上的角标显示正在进行的对局数。数字输入框可以计算算式：`40*60`、`15+10`，支持 `+ - * /` 和括号，按 Enter 或离开输入框时计算结果；按 Esc 恢复输入框原来的值。

### 棋盘及其按钮
<!-- en: boards-and-their-buttons 1ed997f4 -->

在每个显示对局的棋盘下方（*对局*标签页中的回放、*实时*中关注的对局、分离的棋盘、棋盘页面），有一排小按钮，分别用于回到初始局面、上一步、下一步、最后一步，以及翻转棋盘；它们的工具提示中给出了对应的按键，按键的作用相同：← → Home End，以及 F 翻转。喜欢用键盘的人可以隐藏这些按钮：**设置** > *外观* > *棋盘下方的导航按钮*、在按钮上点击右键，或使用命令面板（*隐藏棋盘下方的导航按钮*，用*显示棋盘下方的导航按钮*恢复）。在着法列表上滚动鼠标滚轮只会滚动列表，不会切换着法。在任何棋盘上按 **A** 会在[棋盘](#棋盘)页面打开它的局面并进行分析。

### 版本与新版本
<!-- en: version-and-new-versions 70e3e9a2 -->

版本号显示在窗口标题和**设置**中，设置中的*复制*会将版本号连同系统信息复制到剪贴板，便于提交错误报告。*有新版本时通知我*（默认关闭）会在启动时于后台向 GitHub 查询最新发布版本，每天最多一次；有更新的版本时，主页会提示，并提供*下载页面*（GitHub 上该版本的发布页面，在浏览器中打开）、*新功能*（其发布说明）和*隐藏*（直到下一个版本）。程序不会下载或安装任何东西，失败（没有网络、无法访问 GitHub）只会写入日志。

### 报告问题
<!-- en: reporting-a-problem 3e4e5989 -->

*报告问题…*（位于**设置**、**日志**页面、命令面板中，以及启动失败时的消息里）会在浏览器中打开 GitHub 上的一个新问题，基于错误报告表单，并已填入版本、系统（操作系统、处理器、内存、显卡及其驱动）和日志的最后几行。发送前请阅读一遍，删去不想公开的内容（路径、引擎名称），并说明你做了什么、预期的结果是什么、实际发生了什么。程序本身不会发送任何内容。想法和建议也提交到同一个地方：*New issue*，然后选择 *Idea*。

### 窗口大小和位置
<!-- en: window-size-and-place 892d41c4 -->

窗口按上次关闭时的样子打开：大小、在各屏幕上的位置、是否最大化。如果它原来所在的屏幕已不存在（拔掉了显示器），窗口会在主屏幕中央打开；如果原来的大小已不适合屏幕（分辨率降低），则以默认大小打开。拖出窗口的面板（例如分离的棋盘）也会回到原来的位置（`layout.ini`），如果它们所在的屏幕已不存在，则回到窗口内。Wayland 不允许程序选择窗口的位置：在 Wayland 下，只会恢复大小和最大化状态。

### 窗口的绘制
<!-- en: drawing-the-window caff7bef -->

窗口使用 OpenGL 3.2 绘制。在没有 OpenGL 3.2 的环境中（没有 3D 加速的虚拟机、远程桌面、老旧的服务器），程序改用 SDL 自带的渲染器绘制：Windows 上为 Direct3D 11，或 OpenGL 2.1，或仅用处理器。日志会说明使用的是哪一种，以及为什么没有使用 OpenGL；**设置** > 渲染中也会显示，使用 OpenGL 绘制时还会显示显卡的名称。那里的*软件渲染*（或在命令行中使用 `--software`，仅对一次启动有效）让处理器从下次启动起绘制窗口，适用于出错或崩溃的显卡驱动。这种方式占用更多处理器时间，只重绘发生变化的部分（以及会动的部分，例如时钟：在鼠标和键盘闲置时每秒重绘 15 次而不是 30 次），绘制直角，并且工作区的面板浮动在主窗口内部，而不能拖到另一块屏幕上。在 Wayland 下（以及在 macOS 上），处理器绘制的画面仍然通过显卡驱动显示；如果没有显卡驱动，请用 `SDL_VIDEODRIVER=x11` 启动程序。所有绘制方式都不可用时，程序会在退出前显示一条消息说明这一点。

### 外观
<!-- en: appearance decda352 -->

**设置** > *外观*决定程序中每个棋盘的样子（实时平铺和所关注的对局、分离的棋盘、大屏幕、*对局*中回放的对局、*开局*标签页、开局库中的开局），选项旁边有一个小棋盘，显示所选的效果：

![设置 > 外观：棕色棋盘和 Celtic 棋子](screenshots/appearance.png)

- **棋盘**：格子的颜色，浅色主题和深色主题各有一套（绘制的是当前主题的棋盘）。可以选择预设（*蓝灰色*，即早期版本的颜色；*棕色*；*蓝色*；*绿色*；*灰色*），或者*自定义*：点击*浅色格*、*深色格*或*上一步*会打开取色器，修改任何一种颜色都会让棋盘以原有的颜色为基础变为自定义棋盘。*上一步*的颜色叠加在上一步着法的两个格子上，其透明度让格子本身的颜色透出来。
- **棋子**：程序内置的一套棋子（*Cburnett*，默认；*Chessnut*；*Celtic*；*Fantasy*；它们的作者和许可证见工具提示和 `ATTRIBUTION.md`），或者*自己的文件夹…*：一个包含 12 张 SVG 图片的文件夹，文件名为 `wK.svg`、`wQ.svg`、`wR.svg`、`wB.svg`、`wN.svg`、`wP.svg` 以及 `bK.svg` … `bP.svg`（白方和黑方的王、后、车、象、马、兵）。这些图片和内置棋子一样用 nanosvg 绘制：支持简单的形状、填充、描边和渐变；不支持文字、滤镜和嵌入的图像。如果某个文件缺失、大于 1 MB 或不是可以绘制的图片，页面会指出是哪个文件以及原因，在此期间绘制默认棋子；文件修复后，点击*重新读取*重新读取该文件夹。直播网页始终使用默认棋子。
- **走棋声音**（默认关闭）：*每步棋发出声音*会为所关注对局的每一步播放一声短促的敲击声（在*实时*和大屏幕上），吃子时声音更重；平铺中的其他对局不发声。*音量*，以及*试听走棋* / *试听吃子*用于试听。声音由程序生成（没有声音文件）；只在开启声音时才打开音频设备，如果没有音频设备，日志会说明原因，程序保持静音。

- **棋谱中使用棋子图形**（默认开启）：棋盘页面的着法，包括着法区和分析的变化中的着法，都用上面所选那套棋子的图形书写（Nf3 写成一个马的图形加 f3）；关闭时用字母书写。

命令面板中也有这些选项（*棋盘颜色：棕色*、*棋子：Celtic*、*开启走棋声音*等）。它们保存在配置文件夹中的 `settings.json` 里；在便携模式下，棋子文件夹以相对于程序文件夹的路径保存。

**引擎标志**：在**引擎**页面中，引擎的信息卡上有*标志* > *选择…*，可选择一张 PNG、JPEG 或 SVG 图片，最大 2 MB（长宽各不超过 4096 像素），显示在*实时*、大屏幕和直播网页中引擎名称的旁边。图片会复制到配置文件夹的 `logos` 文件夹中，因此原图可以移动或删除，配置文件夹也可以整体搬移；*移除*会去掉标志（以及它的副本，除非另一个引擎也在使用它）。引擎在下棋时也可以更换标志。

### 3D 棋盘
<!-- en: the-3d-board cc0dd596 -->

**设置** > *外观* > *3D 棋盘* > *棋盘页面的棋盘以 3D 显示* 会以三维方式绘制[棋盘](#棋盘)页面的棋盘，如同一副真实棋盘的照片（默认关闭；其他所有棋盘仍为平面）。显卡以路径追踪计算它：画面静止时会细化几秒钟，每帧占用显卡几毫秒，然后显卡停止工作；棋盘旋转时，会先显示一幅较粗糙的画面。此时*外观*中的小棋盘也会以 3D 绘制，旁边的选项一改变就能看到效果：

- 布光，如同摄影师为静物布光：*摄影棚*、*低调*、*高调*、*展厅*、*窗光*、*黄金时刻*或*比赛大厅*；
- *曝光*：比该布光更亮或更暗，以档为单位，每一档使光线加倍或减半；
- *质量*：画面在停止前由多少个采样组成，默认 512；较少的采样可在比赛期间减轻处理器集成显卡的负担；
- *清漆*，从打蜡的哑光木头到能映出灯光的漆层；*光泽*，从缎面到镜面；
- *默认*恢复初始的曝光、质量、清漆和光泽；布光保持不变。

平面棋盘显示的内容在这里都有：评估条、最后一步、拿起的棋子及其可走的位置、被将军的王、分析的箭头（箭头会隐约透过棋子显示）、走这步棋的引擎预期的应着（虚线）、该步的评判（格子上方的标记），以及代替对局显示的变化的边框。左键单击选择一个格子，与平面棋盘相同，点在棋子上或棋子后面的棋盘上都可以；也可以拖动棋子，它的虚影会跟随指针（见[棋盘](#棋盘)）。按住右键并移动鼠标可绕棋盘旋转（不移动的右键单击仍会放下拿起的棋子），滚轮拉近，单击滚轮恢复视角；翻转棋盘（F）会让镜头转半圈。

3D 棋盘需要 OpenGL 3.3。如果窗口不是用它绘制的（[窗口的绘制](#窗口的绘制)中的软件渲染器、某些虚拟机和远程桌面），棋盘保持平面，*外观*会说明原因。棋子是 clarkerubber 的 Staunton-Pieces，采用 MIT 许可证；*外观*中有指向它们的链接。

## 主页
<!-- en: the-home-page 40031a16 -->

**锦标赛**页面是一个控制室：正在进行的和需要你处理的排在最前面，然后是其余的内容。

- **开始使用**：在第一个锦标赛开始之前显示，列出[快速入门](#快速入门)的各个步骤（添加引擎、设置锦标赛、开始比赛），每一步都有对应的按钮，完成后打勾；还有*阅读快速入门*，在指南面板中打开快速入门。*隐藏*可以收起这张卡片。
- **全部暂停**（位于*打开文件夹…* 和*新建锦标赛*旁边）暂停正在进行的锦标赛（不再开始新的对局对，进行中的对局会下完），并挂起队列：在点击**全部继续**之前，队列中的锦标赛都不会开始；点击后会恢复这些锦标赛并让队列继续，如果在此期间有锦标赛结束，队列会立即继续。
- **核心**：本机的硬件线程数，正在进行的对局占用的线程数，其余为空闲。由于两个引擎轮流思考，一局对局占用的线程数等于其两个引擎中较大的 `Threads`；条形图显示每个锦标赛的名称和它占用的数量，鼠标悬停时显示详细信息。
- **需要处理**：有需要处理的事项时出现，每一项都就地提供修复方法：无法启动的引擎（见[无法启动的引擎](#无法启动的引擎)：*重试*、*退赛…*、*替换…*、*引擎日志*）；因错误或因引擎而停止的锦标赛，附有停止的原因、*打开引擎*、*打开日志*、*继续*、*打开*和*隐藏*；剩余空间不足以下一整夜对局的磁盘（剩余空间不到 1 GB，或者对于小于 500 GB 的磁盘不到 2%），即锦标赛文件夹所在的磁盘或某个正在进行的锦标赛所在的磁盘，每分钟检查一次，附有*打开文件夹*和*更改锦标赛文件夹…*（新锦标赛的存放位置，与**设置**中相同）。
- **进行中**：每个正在进行的锦标赛一张卡片：名称、格式、时限和状态，一个进度条（计划对局中已下的对局，以及正在进行的对局），预计结束时间，以及谁领先：排名第一的引擎及其相对于全体对手的等级分和积分（淘汰赛：剩下的选手；团体赛：各队的比分及其 Elo），比赛中领先的引擎及其 Elo 和比分，或者 SPRT 的 LLR 及其边界，然后是 Elo 和比分。*打开*进入它的工作区，*暂停*暂停它。可以恢复的锦标赛改为显示在*已中断*下，附有*继续*。各锦标赛的权重和核心见[同时进行多个锦标赛](#同时进行多个锦标赛)。
- **队列**：等待中的锦标赛，每个都显示其时长和开始时间，以及全部结束的时间（见[队列与重新开始](#队列与重新开始)）。
- **最近完成**：最近完成的五个锦标赛及其结果：比赛的比分、SPRT 的结论、淘汰赛的冠军（决赛的胜者）、团体赛的比分，或者排名第一的引擎及其对局得分。比赛有*重新开始，使用…*，此外还有*克隆*（见[队列与重新开始](#队列与重新开始)）和*打开*。
- **稳定性**：过去 24 小时内的崩溃或卡死、超时判负和非法着法，空闲内存和已安装的内存，以及正在运行的引擎进程；然后是输掉这些对局最多的三个引擎，附有*打开引擎*和*打开文件夹*（锦标赛的 `logs` 文件夹保存每局异常结束的对局的引擎日志）。第 20 步之前的超时判负会单独区分出来：这更常见于引擎设置不当（线程过多、哈希太大无法及时分配、每局都加载网络、启动缓慢），而不是其时间管理的问题。
- **所有锦标赛**：配置文件夹中的所有锦标赛，最新的在前，附有*打开*、*克隆*和*文件夹*；点击标题可以折叠这个区域。已结束锦标赛的结果在鼠标悬停时显示，覆盖在其状态之上。

命令面板中也有这些操作：*全部暂停*、*全部继续*、针对最近结束的比赛的*重新开始 …，使用…*、针对当前显示的锦标赛和最近完成的锦标赛的*克隆 …*、*打开锦标赛文件夹*和*更改锦标赛文件夹…*。

<!-- en: engines 4f15155a -->

**引擎**页面就是引擎库：左侧是列表，右侧是所选引擎的信息卡。

### 添加和检查引擎
<!-- en: adding-and-checking-engines ebf41ee1 -->

**添加…** 登记一个 UCI 可执行文件。程序会启动该引擎一次，读取它的名称、作者和选项。选项在表格中编辑：修改过的值会高亮显示，并且只有与引擎默认值不同的值才会在每局开始时通过 `setoption` 发送。`Threads` 和 `Hash` 排在最前面。

- **创建副本**为同一个程序文件创建第二个条目，使用不同的选项（不同的 `Hash`、棋力等级、不同的网络文件等）。条目在首次添加时以 UCI 的 `id name` 命名，之后可以重命名。
- **检查**会启动引擎，测量它响应 `uci` 和 `isready` 的速度，并让它走一步棋；然后运行 fastchess 的 UCI 合规性检查步骤（`id name` 和 `id author`、从 FEN 设置的局面和带着法的局面、使用每种棋钟的 `go`、带整数评分的 info 行等），直到第一个失败的步骤为止。结果（✓ 或错误信息）连同日期显示在引擎旁边，*UCI 合规性报告*列出各个步骤，以及引擎在失败的步骤之后输出的内容。以 xboard 协议通信的引擎只进行第一部分。
- **控制台…** 在任何锦标赛之外与引擎对话：引擎以引擎库中的程序、参数和工作目录启动，UCI 引擎会收到 `uci`，然后是引擎库中的选项值。输入的行原样发送（Enter；上、下方向键调出之前的行），日志显示每一行及其时间，发送的行标记为 `>`，错误输出标记为 `!`。按钮可以发送常用命令（`isready`、`position startpos`、`go depth 10`、`go infinite`、`stop` 等；对于 WinBoard 引擎则是 WinBoard 的命令，除非勾选了*通过适配器*，否则使用它自己的协议与它通信）以及棋盘页面的局面。*复制*和*保存…* 用于保存日志。控制台显示在引擎设置的位置（*设置*返回引擎设置，控制台保持打开）；*关闭*结束引擎。锦标赛进行时，该引擎的搜索会占用锦标赛对局的核心：控制台会提示这一点。控制台中的引擎不是锦标赛的进程：锦标赛结束不会结束它。
- **快速测试**与引擎自身或另一个引擎下一场短比赛：从 5 个局面（其中一个含吃过路兵）出发，以 10+0.1 下 10 局，使用与锦标赛相同的代码，进行时显示在它的工作区中。结果显示在引擎旁边：比分，超时判负、崩溃和非法着法，以及它用掉的棋钟时间所占的比例，由此可以看出引擎是否下得太快或太贴近超时。它的将杀 PV 会被检查（见 [PGN 及其他](#pgn-及其他)中的*检查将杀 PV*）。只保留最后一次快速测试，保存在配置文件夹的 `tests/` 中（连同其异常结束的对局的引擎日志）。

### 大型引擎库
<!-- en: a-large-library beb231ed -->

- **分组**：用逗号分隔的自由标签（`pool A`、`list 40/15` 等）。列表可以按分组筛选或搜索，一个分组可以一键加入锦标赛。*备注*：关于该引擎需要记住的任何内容。*标志*：显示在*实时*、大屏幕和直播网页中其名称旁边的图片（见[外观](#外观)）。
- **搜索和筛选**：所有引擎搜索（引擎库，以及其他页面中的引擎列表）都会匹配名称、引擎报告的名称、作者、程序路径或备注；状态筛选可以显示正常工作的、失败的或已改变的、从未检查过的、程序已丢失的、使用 WinBoard 协议的或已停用的引擎。按住 Ctrl 或 Shift 点击可以选中多个引擎：*检查*（逐个进行，锦标赛进行时不进行）、*添加到分组…*、*移除…*。*更多…* 可以检查从未检查过的引擎（*检查尚未检查的*）并移除程序已丢失的条目。保存文件或文件夹的字符串选项（`EvalFile`、`SyzygyPath` 等）带有一个 *…* 按钮。
- **停用**（在信息卡上设置，或通过右键菜单为所有选中的引擎设置）：引擎留在引擎库中，显示为灰色，但不出现在引擎选择列表（设置、测试集、快速测试、重新开始、向正在进行的锦标赛添加引擎）中，也不包括在*检查尚未检查的*中。已经包含它的锦标赛或设置会保留它。
- **使用 GPU**（在信息卡上）：在显卡上运行的神经网络引擎，例如 Lc0。同时下棋的此类引擎不会多于**设置**中的 *GPU* 数，在一个锦标赛内和各锦标赛之间都是如此（见[同时进行多个锦标赛](#同时进行多个锦标赛)）；从它加入的下一个锦标赛起生效。
- **参考 Elo**：引擎在你信任的某个等级分榜上的等级分。锦标赛或等级分榜可以以它为锚点，锦标赛的对局会在 `WhiteElo` 和 `BlackElo` 标签中带上它（在引擎加入时复制）。*导入…* > *等级分榜，用于参考 Elo…* 可以一次为多个引擎设置参考 Elo（见[导入引擎和等级分](#导入引擎和等级分)）。

### 启动引擎
<!-- en: starting-engines 09d107ba -->

- **读取选项**绝不会阻碍开始。*继续*立即开始：锦标赛使用复制到其文件夹中的引擎。*开始*、队列和快速测试只等待它们要用到的引擎的读取，并优先读取这些引擎；其他任何读取或检查都会被中断，稍后重新进行。需要等待时，按钮上会显示出来（*正在等待 …*，附有*取消*），在此期间不能再开始其他锦标赛。开始还会等待正在运行的测试集；而在快速测试进行时或有开始正在等待时，测试集不会开始。读取、检查和测试集与锦标赛同时运行，锦标赛在各自独立的进程中进行。排队等待读取的引擎可以通过它的菜单安排为下一个读取。
- *每局对局都重启引擎*会为每局对局启动一个新进程，而不是复用原来的进程。否则，锦标赛会为每个仍有对局要下的引擎保留一个等待中的进程，最多 32 个（另加每局正在进行的对局两个），并在引擎下完最后一局后关闭它：在淘汰赛中，一旦输掉它的比赛就关闭；在瑞士制中，当它在最后一轮已没有对局时关闭。
- *启动超时（秒）*（默认 60）是引擎在启动时回复 `uciok`、在每局开始时回复 `isready` 所允许的时间；启动慢的引擎（需要加载大型网络）需要更长的时间。启动失败的引擎会再尝试三次，每次间隔 10 秒，超时时间相同；暂停会搁置这些尝试，但不会消耗尝试次数。之后，它的对局会被搁置，其他对局继续（见[无法启动的引擎](#无法启动的引擎)）。此后创建的锦标赛会将该超时复制到其参赛者中。

### 重新构建的程序
<!-- en: rebuilt-programs 549daa6e -->

- **移动或重新构建的程序**：引擎库记住每个程序（大小、日期、CRC32）。已经不在原处的程序会标记为 **!** 并附有*定位…*，锦标赛不会用它开始。发生变化的程序（新的构建，或者同一路径下换了另一个文件）会自动重新读取它的选项。
- **新构建改变了什么**：如果新的读取结果与上一次不同，引擎会标记为 **Δ**，它的信息卡会列出这些差异，直到点击*关闭*为止：新的 `id name`（如果引擎是按旧名称命名的，附有*重命名为“…”*）和作者，默认值、范围或可选值发生变化的每个选项（之前和现在），新增和移除的选项，以及你为每个选项设置的值（已移除选项的值会被丢弃；新构建不再接受的值显示为橙色）。对于默认值发生变化的选项，或者你的值已不再适用的选项，可以选择*保留我的值*（如果你没有设置过值，则为*保留旧的默认值*：它照旧运行）或*使用新的默认值*；*保留我的所有值*和*全部使用新的默认值*一次为所有选项做出选择。做完所有选择后，提示就会消失，除非还有其他要说明的内容。在点击关闭之前出现的多次构建合并为一条提示，与第一次构建之前的读取结果比较。状态筛选中的*失败或已更改*也会显示这些引擎，命令面板中针对每个引擎有*更改内容*、*保留我的所有值*、*全部使用新的默认值*和*关闭更改提示*。
- **锦标赛的程序**：每个锦标赛都会记录它开始时使用的程序。设置的摘要会对程序自上一个锦标赛（锦标赛文件夹中使用该程序的最新一个锦标赛）以来发生变化的引擎发出警告，如果它的信息卡上有提示，还附有*更改内容*。恢复锦标赛时，如果某个程序在此期间被重新构建或已丢失，锦标赛的页眉会说明这一点，附有*继续*（关闭提示）和*暂停*；锦标赛不会自行停止。

### 导入引擎和等级分
<!-- en: importing-engines-and-ratings 63154f3f -->

**导入…** > *引擎列表…* 读取其他程序的引擎列表：ChessGUI（`ChsGUI_Eng.TXT`，以及它旁边的 `ChsGUI_Cfg.ini` 中的选项）、cutechess 和 Banksia（`engines.json`）、Arena（`ArenaENG.cfg`，在 Arena 的文件夹中：每个引擎的程序、参数、协议，以及 UCI 引擎在 Arena 中设置的选项值），以及其他 INI 格式的列表。如果列表中没有读到任何引擎，会说明这一点，列出已尝试的格式，并提供*某个文件夹中的所有引擎…* 作为替代。

*某个文件夹中的所有引擎…* 导入在一个文件夹中找到的所有程序，并记住该文件夹：之后*刷新：文件夹中的新引擎*只提供此后新加入该文件夹的引擎。找到的引擎会先列出来，可以取消勾选要排除的引擎；已在引擎库中的引擎（相同的程序和参数）会被跳过；其余引擎的选项会被读取；WinBoard 引擎也会被导入。

*导入…* > *等级分榜，用于参考 Elo…* 读取一份粘贴或打开的等级分榜：等级分榜的文本版本或其网页（保存的或复制的）、Ordo 的输出（文本或 CSV），或者由 `name,elo` 行组成的 CSV。榜中的名称对应引擎库中同名的引擎，或者在忽略大小写和空格后名称相同的唯一一个引擎（与导入的 PGN 文件中的棋手一样，见[等级分](#等级分)）。预览显示每个引擎新旧两个参考 Elo，勾选的会被设置，并列出榜中不对应任何库中引擎的名称。榜中的名称常常带有构建信息（`64-bit 4CPU`）：如有需要，可以重命名引擎以与之匹配。

### WinBoard 引擎
<!-- en: winboard-engines 079e4849 -->

**WinBoard 引擎**（xboard 协议，CECP）与其他引擎一样参赛。引擎的*协议*在添加时自动检测（*自动*），也可以手动选择：UCI 或 WinBoard。fastchess 只支持 UCI：WinBoard 引擎通过 fastchess-gui 内置的转换启动（`fastchess-gui --wb2uci ENGINE [ARGS]`，由 fastchess 代替引擎启动），它的选项、`memory`、`cores` 和 Syzygy 路径都变为 UCI 选项。转换以 WinBoard 的方式驱动引擎：使用协议 2 的 feature，对于不发送 feature 的引擎使用协议 1；通过 `setboard` 或编辑模式设置局面；以坐标或 SAN 表示着法；`level`、`time`/`otim`、`st`、`sd`、`nps`；思考输出、认输。列表中标记为 ↔ 的是 WinBoard 引擎。

- 既不支持 `setboard` 也不支持编辑模式的协议 1 引擎（例如 TSCP）只能从初始局面开始：请以着法（PGN 开局库）而不是局面（EPD）的形式为它提供开局。
- 支持 `fischerandom` 变体的引擎可以下 Chess960：`variant fischerandom`，局面使用 X-FEN，易位写作 `O-O`/`O-O-O`，与 WinBoard 发送的方式相同。
- 引擎选项中的 *Scores from White's side*：用于那些按白方视角而不是协议要求的走棋方视角给出评分的老引擎；它们执黑时的评分会被反转。
- 要求每局对局都重新启动的引擎（`feature reuse=0`）在添加时会勾选*每局对局都重启引擎*。
- 在环境中设置 `FCG_WB2UCI_LOG=FILE`，会将与 WinBoard 引擎交换的每一行写入 `FILE`。

## 开局库
<!-- en: books 4cf13005 -->

**添加…** 以一个名称登记一个开局库（EPD、PGN 或 Polyglot `.bin`），并附上描述；对于 PGN 开局库，可设置保留的半回合数，对于 Polyglot 开局库，可设置其变化跟随的深度。之后，设置中的*开局*部分会按名称提供引擎库中的开局库，并显示它们的开局数（仍然可以选择任何其他文件）。*移除*将开局库从库中移除，文件保持不动。

### 检查开局库
<!-- en: checking-a-book 96eee229 -->

所选的开局库会在后台用 fastchess 自己的读取器读取（因此其中的开局与锦标赛下的开局完全一致），并进行检查：

- **非法局面**：双方不是各有一个王、兵在第一或最后一横排、不走棋的一方正被将军；
- **重复**：与之前某个开局局面相同，包括经由换序到达的；
- **颜色互换**：与之前某个开局颜色互换（打算交换颜色下两次的开局库不需要同时包含两者）；
- **对局已结束**：没有合法着法，或子力不足以将杀。

fastchess 会把局面无法下的开局排除在锦标赛之外（缺少王或其他格式错误的 FEN 或 EPD 行、王可以被吃掉、FEN 标签无效的 PGN 对局），每个开局库给出一条警告；这里把它们计为非法局面。着法解析中断的 PGN 对局（格式错误或有歧义的着法）保留其之前的着法。PGN 开局库中以 `%` 开头的行（转义行，PGN 标准将其视为注释；AVT 开局库中有一些）会被忽略，锦标赛也会忽略它们，开局库页面会统计它们（*以 % 开头的行，已忽略*）。

开局库的开局列在下方，可以显示全部开局或只显示有问题的开局，可以按 FEN 的一部分或按着法搜索（PGN 开局库以 SAN 显示其着法）；点击会在棋盘上显示该局面。*用于下一个锦标赛*把它放入设置中（Chess960 开局库会同时开启 Chess960）。*保存清理后的副本…* 写出一个去掉非法局面、重复局面和已结束对局（如果勾选，还包括颜色互换的局面）的 EPD 开局库，并将其加入库中。*作为测试集运行…* 在**测试集**中打开一个 EPD 开局库。

### 创建开局库
<!-- en: creating-books b9c072ab -->

**创建…** 为库生成开局库（命令面板中也有）：

- *生成 Chess324 开局库*：Larry Kaufman 的 Chess324。王和车留在通常的格子上，因此易位与通常相同；每一方的后、象和马在其底线的其他格子（b、c、d、f、g 列）上随机排列，两个象位于不同颜色的格子上。这样每一方有 18 种排列，白方和黑方独立选择：*全部 324 个局面…*，或*仅 18 个对称局面…*，即黑方棋子与白方位于相同的列上。它们是普通局面，写入一个 EPD 文件（建议放在库中开局库的旁边，或配置文件夹的 `books/` 中），任何引擎都可以下，不需要 Chess960。
- *生成 Polyglot 开局库…*：从一个 PGN 文件的对局生成一个 Polyglot 开局库（`.bin`），与 Polyglot 的 `make-book` 的做法相同，使用的转换与把参赛者的 PGN 开局库转换为 Polyglot 开局库的转换相同。它的表单显示在开局库详情的位置，需要填写 PGN 文件（如果列表中选择了 PGN 开局库，则为该开局库）、**深度**（每局对局进入开局库的半回合数）、一步着法在其局面中被保留所需的**最少对局数**（Polyglot 的 `-min-game`；其余的因下得太少而被排除）、**权重**：*按得分*（走出该着法一方的得分：胜 2、和 1、负 0，与 Polyglot 的计法相同；没有结果的对局会被排除，所有对局都输掉的着法也会被排除）或*按次数*（走出该着法的对局数），以及（如果勾选）**等级分**：只计入等级分至少为该值的棋手的着法，依据对局的 `WhiteElo` 或 `BlackElo` 标签（没有该标签的棋手会被排除）。*生成…* 会询问开局库的写入位置（默认在 PGN 文件旁边），然后在后台读取对局，在表单旁边和列表末尾显示进度和*取消*；生成的开局库按该格式的要求以键排序，然后加入库中，其选项写在描述中。控制台会说明有多少对局进入了开局库、多少被选项排除、多少无法读取。

## 棋盘
<!-- en: board 0bbd00c9 -->

棋盘页面显示来自任何地方的一局对局或一个局面：在程序的任何棋盘上（*实时*标签页平铺中的对局或所关注的对局、*对局*标签页的棋盘、*开局*标签页的棋盘、开局库中某个开局的棋盘）按 **A**，会在这里打开它的局面并进行分析；在棋盘页面上，A 开始和停止分析。*回到锦标赛*（或*返回*）回到原来的页面。它的棋盘可以以 3D 绘制：见[3D 棋盘](#3d-棋盘)。

棋盘在左边，棋手位于其上方和下方；右边从上到下依次是分析、着法（着法表格、对局复盘以及文件中的对局分别位于各自的标签页中）和对局图表。页面的副标题说明这是一局什么样的对局：它的赛事和轮次、结果、时限、ECO 代码和开局，以及它是如何结束的。

在棋盘上用鼠标走棋：先单击棋子，再单击目标格；或者把棋子拖到那里。拖动时，棋子跟随指针，它将落下的格子会被着色；在别处松开时，棋子回到原位并保持选中，可以再单击走棋。在 3D 棋盘上，棋子的半透明虚影跟随指针，悬浮在棋盘上方，并从它前面的棋子后方经过，画面保持不变；松开时棋子本身才移动。

### 打开、粘贴和摆放局面
<!-- en: opening-pasting-and-setting-up-a-position 3778ddb5 -->

- **打开 PGN…** 在后台读取任何 PGN 文件（也可以把文件拖放到窗口上），并显示进度条：包含数百万局对局的文件只需几秒钟，其中的对局列在着法旁边的一个标签页中，可以按输入的内容筛选（输入的每个词都要在棋手、赛事、地点、日期、轮次、开局、ECO 代码或结果中找到）。点击即可显示一局对局。它的着法的评估会绘成图表：程序会读取 cutechess 和 fastchess 的注释（`{+0.35/18 1.2s}`）以及 lichess 和 ChessBase 的 `[%eval 0.35]`（白方视角，将杀写作 `#-3`），也会读取 `[%clk 0:01:23]` 中的棋钟时间。对局中的变化会保留下来（见[变化](#变化)）。FEN 标签无法下的对局会被拒绝，对局的着法在第一个无法读取的着法处截止。
- **粘贴**（在页面上按 Ctrl+V）读取剪贴板：FEN，或 EPD 行的四个字段；包含一局或多局对局的 PGN（与文件一样列出）；从初始局面开始的着法列表，可以是 SAN 格式，带或不带回合数（`1. e4 e5 2. Nf3`），也可以是 UCI 格式（`e2e4 e7e5`）。无法下的局面会被拒绝并说明原因（缺少王、兵在第一横排、不走棋的一方正被将军）。如果易位权对应的王或车不在通常的格子上，或者易位权以列字母书写（`HAha`），该局面就成为 Chess960 局面。也可以拖放 `.fen` 或 `.epd` 文件。
- **编辑局面**在棋盘上摆放局面：点击放置所选的棋子（再次点击将其拿走），右键点击拿走棋子；还可以设置走棋方、回合数、易位权（只有王和车位于所需的位置时才提供）、吃过路兵格（只能在刚走了两格的兵的后方）和 Chess960。下方的 FEN 随棋盘变化，在那里输入 FEN 也会设置棋盘。局面可以下时才提供*完成*，点击后将局面放到棋盘上。
- *复制 PGN*（在着法各标签页的右侧）复制显示的对局，包括它的标签、着法（如果有引擎评分，则作为注释）和变化。
- **棋盘**：棋盘下方的按钮和 ← → Home End 用于浏览着法，F（或最后一个按钮）翻转棋盘；点击一个棋子再点击一个格子即可走棋（升变的兵会询问升变成什么棋子）。*复制 FEN* 复制该局面。

### 棋手
<!-- en: the-players 1f4f551f -->

对局有棋手时，显示在棋盘的上方和下方：每位棋手的名称、其引擎对它上一步的评估（白方视角的评分和深度，以小标签显示）、它走的着法和所用的时间，或者*轮到走棋*，右侧是它走完上一步后的棋钟，轮到它走棋时加框显示。如果对局的着法带有 `[%clk]`，棋钟就取自它们；否则根据对局的 `TimeControl` 标签（`300+2`、`10+0.1`：秒数和加秒）和每步所用的时间重新推算，开局库着法不计时间。

### 分析
<!-- en: the-analysis 1e6120de -->

引擎库中的一个引擎搜索显示的局面，并跟随棋盘变化。卡片上先显示它的引擎，然后是一个按钮，上面写着它的*线程*、*Hash*（0：引擎自己的值）和*变化*（MultiPV），点击即可打开：这些是分析专用的设置，会保留到下次使用，既不改变引擎库中的引擎，也不影响任何锦标赛（引擎库中的其他选项值按对局发送它们的方式发送）。右侧显示棋盘页面所用的线程数及本机的线程数，锦标赛进行时以警告色显示（其工具提示说明锦标赛的对局占用了多少线程：分析会与它们争夺资源）。

搜索信息以小方块显示（深度和 seldepth、节点数、速度、时间、残局库命中数、Hash 的占用率），引擎提供时还显示胜、和、负的概率（`UCI_ShowWDL`），以及每条变化：它的评分（白方视角，最佳变化的评分单独突出显示）、深度，以及分两行显示、带棋子图形的着法（见[外观](#外观)）。鼠标悬停在变化中的某个着法上时，棋盘会显示走完该着法后的局面，并加框；点击则把这条变化一直走到该着法。每条变化的第一步以箭头绘出，最佳变化的箭头颜色更深（**设置** > *外观* > *棋盘页面上的分析箭头*可关闭它们；变化仍会显示着法）。

**威胁**（X）让引擎的另一个进程在交换走棋方后搜索该局面：即对手如果再走一步时的最佳着法，以红色箭头绘出，并写在变化下方（走棋方被将军时没有威胁）。

显示其他页面时，分析会暂停等待，回到棋盘页面时继续；*停止分析*（或 A）停止分析，导航栏*棋盘*按钮上的圆点表示分析正在运行。分析的引擎不是锦标赛的进程：锦标赛结束不会结束它。停止后，引擎仍保持启动，供下一次搜索使用，并保留其哈希表（以及神经网络引擎的 GPU 内存）：引擎旁边的电源按钮*卸载引擎*（命令面板中也有）会结束它以及威胁分析的引擎。

### 分析整局对局
<!-- en: analysing-a-whole-game a7e6166c -->

**分析对局**（G，位于页面的工具中或图表的标题栏中）让分析引擎（使用它的线程和 Hash，一条变化）在后台搜索对局的每个局面，先是每个局面 20 毫秒，之后每一轮用四倍的时间再搜索一遍（80 毫秒、0.3 秒、1.3 秒、5 秒……），直到用按钮旁的箭头所选的时间为止（每个局面 0.3 秒、1.3 秒、5 秒、20 秒，或*直到手动停止*）：图表在一两秒内出现，每一轮都变得更精确。局面从最后一个到第一个依次搜索，这样引擎的 Hash 中就保存着某个局面之后的内容（实测：在相同时间内，与从第一个到最后一个搜索相比，结果与长时间搜索的差距缩小约 16%），棋盘上的局面最先搜索。图表的标题栏显示当前轮次、每个局面的时间和进度，时间条下方的一条细带显示每个局面已得到的搜索时间；*停止*（或 G）停止分析。

每步棋根据走棋方失去的获胜机会来评判，依据是分析在这步棋之前和之后的评分（lichess 的计算方法：0.00 时为 50%，+1.00 时约为 59%）：失去 10 个百分点为缓着（`?!`），20 为错着（`?`），30 为败着（`??`），标记在该着法之后、图表上和棋盘上；引擎自己会走的着法永远不会被标记。着法依据最后一个完整的轮次来评判；最后一轮改变了的标记显示为空心，直到下一轮确认为止。N 和 Shift+N（或导航按钮旁边的按钮）转到下一个和上一个被标记的着法。

每个完整的轮次都与对局一起保存（在配置文件夹的 `analyses/` 中）：同一局对局从任何地方再次打开时，都会立即显示它，G 会从已完成的轮次继续。整局分析在自己的线程中运行，使用自己的引擎进程，其线程计入核心预算；棋盘的分析（A）会让它暂停，如果 A 对对局中某个局面的搜索时间比该轮更长，就用 A 的结果代替该局面的值。

**多个分析**：图表图例中的*+ 引擎*让引擎库中的另一个引擎也来分析这局对局，每一轮所用的时间相同。每个分析在图表和棋盘上都有自己的颜色（棋盘的分析关闭时，它的最佳着法以箭头显示），在*本步*中有自己的一行，在复盘中有自己给出的准确率。它们一轮一轮同步进行，核心数允许时同时运行，否则依次运行。由一个分析来评判着法（第一个；在图例中右键点击另一个分析可让它成为评判者，或将其移除）；如果各分析对某步着法的评判不一致，标记显示为空心。比较不同的引擎时，获胜机会比厘兵（centipawn）更合适，因为厘兵的数值因引擎而异：如果引擎提供 WDL，获胜机会就取自它的 WDL。

### 对局图表
<!-- en: the-game-graph 14e02bad -->

着法下方是对局的图表，与*实时*和*对局*中的相同：

- **评估**：担任评判的分析以白色和黑色区域显示（白方的优势在线的上方，黑方的在下方），下棋的每个引擎在它自己的着法上以其颜色的曲线显示，其他分析以虚线显示；被标记的着法显示在曲线上；超过 ±6 的值以警告色沿边缘绘出。没有分析时，区域为两个引擎评估的平均值。
- 开局库着法以斜线填充，轴下方标出各个阶段（开局；中局从第一个除王和兵以外最多剩 10 个棋子、或某一底线上少于 4 个棋子的局面开始；残局从最多剩 6 个开始，与 lichess 划分对局的方式相同），残局库已知的区域着色显示，底部标出回合数。
- 轴下方是每步所用的时间：白方的向上，黑方的向下。

它的标签页：*胜率*（引擎提供 WDL 时取自 WDL，否则用 lichess 的公式）、*胜/和/负*（引擎报告的比例，白方胜的比例在最下面）、*时间*（附决定时间）、*深度*（附 seldepth）、*节点*、*速度*、*残局库命中*、*一致性*（两位棋手的评估相差多少，每步与前一步相比，以及各分析在每个局面上的评估相差多少）和 *PV 一致率*（一个引擎的 PV 有多少个半回合与另一个引擎所预测的相符）；对局没有数值的标签页不显示，放不下的标签页放在 `⋯` 菜单中。鼠标悬停时显示该着法以及每个引擎的说法；点击或拖动可转到该着法。点击图例中的某条曲线可隐藏或显示它；右侧的箭头折叠图表。

### 本步
<!-- en: this-move a4a908f8 -->

着法下方是关于所显示着法的信息：走这步棋的引擎给出的数据（评分、深度和 seldepth、时间、节点数、速度、残局库命中数，以 PGN 中记录的为准）、它预期这步之后的变化、每个分析的结论（失去的获胜机会比例、评判、最佳着法及其评分），以及在有残局库时，这步棋之后的结果和这步棋是否保持了之前的结果。*显示*把一条变化摆到棋盘上而不改动对局：显示走完它之后的局面，棋盘加框，并在上方注明这是什么变化；按 Esc、点击棋盘或在对局中移动都会恢复对局。在棋盘上，着法的评判以徽标显示在它的格子上，其引擎预期的应着以虚线箭头显示。

### 变化
<!-- en: variations 7932794c -->

在棋盘上走出一步与对局实际走法不同的着法会开始一个变化：对局本身保持原样，连同它的分析和图表。着法中的变化写在括号里，紧跟在它所替代的着法之后，可以嵌套并带有编号；点击一个着法会转到那里，*回到对局*返回该变化分出时的局面。在变化的着法上点击右键可以提升它（它成为其分出的那条线，那条线在它之后的着法则成为变化）、删除它以及从它分出的变化，或者复制它。*复制 PGN* 会写出变化，打开的 PGN 文件中的变化也会被读取（注释、回合数、注解符号和结果会被跳过；无法下的着法只结束它所在的变化）。图表、分析和评判都属于对局本身；在变化上时，图表会标出它离开对局的位置。

### 着法、表格和复盘
<!-- en: the-moves-the-table-and-the-review 7880f8d8 -->

**着法**以连续文本的形式写出对局：使用棋子图形（见[外观](#外观)），开局库着法显示为灰色并标出开局库的结束处，评判以颜色显示，当前着法加框；鼠标悬停在着法上时显示其引擎的说法和对它的评判。**表格**列出每步着法及其引擎的评分（白方视角）、深度和时间，用一个条形表示时间，被标记的着法着色显示。

**复盘**，在对局分析完成后显示：每一方的准确率（lichess 的计算方法：每步棋的准确率根据它失去的获胜机会计算，紧张时刻的着法权重更大）、缓着、错着和败着、以厘兵计的平均损失、分析也会走的着法所占的比例、其引擎的平均深度和平均时间；在开局、中局和残局中各自的准确率；有多个分析时，每个分析给出的准确率。接下来是关键时刻，点击即可转到：转折点（失去最多的那步棋，附最佳着法）、其他错着和败着、两个引擎连续两步意见相差 1.5 个兵或以上的位置、残局的开始以及进入残局库的开始。*谁先看出来*针对转折点，说明下棋的每个引擎和每个分析最早在哪一步给了得利一方一个兵或更多的优势。*复制含分析的 PGN* 写出对局，包括每个局面的评估（`[%eval]`）、以 NAG 表示的评判，以及在被标记的着法之后分析更倾向的变化；*复制为 BBCode* 生成适合发到论坛的复盘内容。

### 棋盘页面上的残局库
<!-- en: tablebases-on-the-board-page 721b71dd -->

使用设置中的 Syzygy 文件夹（*裁定* > 残局库），棋盘页面会查询对局的每个局面：图表为残局库已知的区域着色，*本步*说明这步棋之后的结果，以及这步棋是保持了之前的结果还是把它葬送了，复盘则标出残局库接管的位置。查询每个局面时都当作刚走了一步吃子或兵的着法，这样做是精确的，除非临近 50 步规则。这些残局库属于程序的进程：当锦标赛在该进程中进行时，不会查询它们。

### 从局面下一局对局
<!-- en: playing-a-game-from-a-position 7e83c318 -->

**下一局…** 让引擎库中的两个引擎（或者你和其中一个引擎，见下文的*人类*）从棋盘上的局面下一局对局（*白方*和*黑方*，`<->` 连同棋钟交换两者），各有自己的棋钟（分钟数和以秒计的加秒；*双方相同*，或者为了时间让步各设一个），如果勾选，还会交换颜色再下第二局。引擎以引擎库中的选项值启动，WinBoard 引擎通过适配器启动。棋盘随对局的进行而跟随（在对局中往回翻会停止跟随，直到再次到达对局末尾，或者点击*回到当前着法*），并显示棋钟、走棋方的搜索和*停止*（结束对局且不记结果）。对局在以下情况下结束：将杀、逼和、子力不足、50 步规则、三次重复、非法着法、引擎停止，或者超时判负（棋钟会额外给 0.1 秒，让着法有时间传到）。每局对局结束时都会追加到配置文件夹 `games/` 中的一个 PGN 文件里（以日期和引擎命名，带有 `Termination` 标签），*打开这些对局*会在棋盘上列出它们。

这些对局由 fastchess-gui 自己的引擎客户端进行，独立于任何锦标赛：它们可以在锦标赛进行时下，而不会影响锦标赛。它们的线程数（两个引擎中较大的那个，因为两者轮流思考）计入核心预算；如果正在进行的锦标赛的对局和分析已经占满本机，卡片会说明这一点，并以*仍然开始*代替*开始*。对局开始时分析会停止，否则它会与对局的引擎争夺资源。

**人类**位于*白方*和*黑方*列表的最前面，代表你自己：选择它就由你下这一方；你的着法用鼠标在棋盘上走，平面棋盘和 3D 棋盘都可以（兵走到底线时会询问升变的棋子）。每局开始时棋盘会翻转，让你这一方在下方（*翻转*仍然可以翻转它）；只有轮到你时才能拿起你的棋子（卡片上显示*轮到你走棋*）；当你在查看之前的着法时，点击棋盘会回到对局。你的棋钟和引擎的一样走，也会超时判负：取消勾选*双方相同*，就可以给自己比引擎更多的时间。你下棋时，引擎的想法会被隐藏（它的评分、深度和变化，因此评估条和图表曲线也一样）；结束后的对局会包含这些信息，可以直接用*分析对局*。*认输*可以随时结束对局，由引擎获胜；如果有第二局，它会接着开始，你的颜色互换。你的对局以你的登录名保存，核心预算中只计算引擎。不能悔棋；除非引擎的信息卡设置了较低的棋力（如果引擎有 `UCI_LimitStrength` 和 `UCI_Elo`，或 `Skill Level`），否则引擎以全力下棋。

## 测试集
<!-- en: test-suites 42c2b2ba -->

**测试集**页面运行 EPD 测试集：带有最佳着法（`bm`）、应避免的着法（`am`）的局面，或者对于 Strategic Test Suite，带有多个着法的得分（`c0 "f5=10, Be5+=2"`）的局面。

- **测试集**：一个 EPD 文件，或库中的一个 EPD 开局库。没有合法局面或不含上述操作之一的行会被排除（显示其数量）。
- **引擎**：引擎库中任意数量的引擎，使用它们的选项；*Hash* 和*线程*为每个引擎强制设定一个值（0 = 每个引擎自己的值）。
- 每个局面的**时间**、**节点**或**深度**。*已找到（半回合）*：一旦某个解作为引擎的首选着法又保持了这么多半回合的深度，搜索就停止（0 = 每次搜索都用完全部时间）。
- **自动并发**：按时间时，为物理核心数 − 1 再除以引擎的线程数；按节点或深度时，为所有硬件线程。

如果引擎的最终着法是一个解，该局面就算解出：是 `bm` 中的一个、不是 `am` 中的任何一个，或者在只有得分时，是得分最高的着法。解题时间是引擎确定该着法的时刻。网格显示各局面对各引擎的结果：✓ 及解题时间，或 ✗ 及所走的着法，以及 STS 得分；总计排在最前面：解出的局面数、它们的平均时间和 STS 分数。完成的运行结果保存在配置文件夹的 `suites/` 中；*与已保存的运行结果比较…* 添加同一测试集之前某次运行的列，用于比较一个引擎的不同版本。*导出 CSV…* 写出网格。

## 新建锦标赛
<!-- en: new-tournament 6d169de4 -->

**锦标赛 → 新建锦标赛**打开设置：一张由折叠的行组成的卡片，说明对局如何进行；参赛者，旁边是引擎库；右侧是实时更新的摘要（对局数、每个引擎的对局数、预计时长、开局、通用设置、时间让步）。上一个锦标赛的设置会被保留，因此再次测试一个引擎的两个版本只需：选择 A 和 B，点击**开始**。

页面上的所有操作都可以用键盘完成：Tab 和方向键在各行、列表和按钮之间移动，Enter 或空格打开一行或一个列表，[参赛者和引擎库](#参赛者和引擎库)的按键在那里也有效。**开始**创建锦标赛并开始比赛；**加入队列**把它留到以后（见[队列与重新开始](#队列与重新开始)）。

### 摘要及其检查
<!-- en: the-summary-and-its-checks 5609344a -->

摘要给出哈希表可能占用的内存：每局同时进行的对局两个引擎进程，加上等待下一局的引擎，每个都按其 `Hash` 计算。超过空闲内存时，摘要会发出警告（系统将使用交换空间），并指出 `Hash` 最大的引擎；超过已安装的内存时，锦标赛不会开始。`--run` 也会给出同样的提示。当**设置**中的内存预算允许同时进行的对局少于并发数时，摘要会说明能同时进行多少局（每局对局占用其两个引擎的 `Hash`，以及它们的进程额外占用的内存），*并发*行也会说明；对于含使用 GPU 的引擎的对局，也会对照 *GPU* 数作同样的说明。摘要还会指出自上一个锦标赛以来程序发生了变化（新的构建）的引擎，如果引擎的信息卡列出了新的默认值或选项，还附有*更改内容*（见[重新构建的程序](#重新构建的程序)）。

会出问题的地方都会指明相关的引擎、资源和修复方法，修复按钮位于该行下方（命令面板中列出同样的修复操作）：

- 找不到程序或工作目录：*打开引擎*（它在引擎页面上的信息卡）、*定位…*；找不到开局库：*定位…*；
- 引擎自身的 `Threads`（它的设置值，否则为默认值：有些引擎会占用所有核心）超过硬件线程数的一半，或者超过同时进行的对局中每局可用的线程数（使用棋钟时按物理核心数计）：*将 Threads 降为 N* 在引擎库中设置该引擎的选项，*打开引擎*。设置中给出的超出本机能力的 `Threads` 会在给出它的地方（参赛者的单元格、通用设置）附上*将 Threads 降为 …*。参赛者列表用 *!* 标记这样的引擎，比赛的引擎则在其下方标出；
- 引擎拒绝的选项值（超出范围、不是可选值之一、引擎已不再有的选项）：fastchess 不会发送它，引擎使用其默认值下棋；
- 锦标赛使用的 Syzygy 残局库：裁定所用的文件夹，以及每个引擎的 `SyzygyPath` 指向的位置（多个文件夹在 Windows 上用 `;` 分隔，在其他系统上用 `:` 分隔）。对于所用的棋子数（裁定的*最大棋子数*，否则为找到的最大的残局库），每个 WDL 文件（`.rtbw`）都必须存在，并且不能有被截断的文件（Syzygy 文件的长度比 64 的倍数多 16 字节；引擎会忽略其他大小的文件，有些引擎遇到它会停止）：*Syzygy 6 子：14 个文件缺失，位于 D:\TB（KRPPvKR.rtbw…）*、*裁定最多 6 子，但只找到 5 子的文件*、*Alpha 的 SyzygyPath 指向一个没有残局库文件的文件夹*，附有*打开文件夹*和*降为 5 子*；工具提示列出这些文件。这些都是警告：裁定和引擎在缺少这些文件的情况下照常工作。只有没有文件夹的裁定，或者文件夹中没有任何残局库的裁定，才会让锦标赛在开始时停止（fastchess 会拒绝它）：*定位…* 选择另一个文件夹。这些文件夹在后台读取，显示摘要时每隔几秒重新读取一次。

开始被拒绝时，会列出同样的问题，附有修复方法和*打开日志*。每个问题都有一个 **?**，打开它在[故障排除](#故障排除)中的条目。

### 配置与模板
<!-- en: profiles-and-templates df08e65d -->

**配置**：前五行，即*格式*、*时限*、*开局*、*裁定*和*引擎设置*，每一行都是一个命名的配置：它的列表用于选择配置，旁边的一行文字说明它下什么（“40 步 15 分，重复”、“和棋 40/8/10 cp · TB 6 子”；它的工具提示以 cutechess 和 fastchess 的写法给出同样的内容，`tc=40/900`、`-draw movenumber=40 movecount=8 score=10`），点击 ✎ 或那行文字，会在其下方就地打开详细设置。仅为本锦标赛做的修改会在配置旁显示一个圆点，它的列表和详细设置中会提供*更新*（配置采用这一修改，对所有使用它的锦标赛和模板生效）、*恢复*和*另存为配置…*（使用新的名称）。程序自带一些预设：

- 时限：10+0.1 和 60+0.6（fishtest 的短测试和长测试）、2+1、40/4、40/15 和 40/20（4、15 或 20 分钟 40 步，重复，与等级分榜的下法相同），以及每步 20 万节点；
- 格式：SPRT 提升 [0, 3] 和无退步 [-5, 0]、1000 局的比赛、循环赛、车轮战、9 轮的瑞士制、淘汰赛和团体赛；
- 裁定：无、标准裁定（从第 40 步起，连续 8 步评分在 10 cp 以内判和；连续 3 步评分达到 600 cp 判负），以及同样的裁定加上最多 6 子的残局库；
- 引擎设置：每个引擎自己的设置，或者 Hash 16、64 或 256 MB，1 个线程，并关闭引擎自带开局库；
- 开局：无开局库，或 Chess960 的 960 个局面。

以预设的名称保存的你自己的配置会取代该预设；删除它（在它的列表中，确认后）会恢复预设，使用它的设置和模板会保留它的值。配置保存在配置文件夹的 `profiles.json` 中，命令面板（Ctrl+K）会列出它们：选择一个即可将它应用到设置中。命令面板还可以按标题打开设置中的每一行，并加载或保存模板。Syzygy 目录不属于任何配置：它们属于这台计算机，由裁定和引擎共用。*并发*和 *PGN 及其他*两行保存的是只属于本锦标赛的内容。

**模板**和**名称**，位于*开始*旁边：模板是整个设置，即每个部分一个配置，加上配置不包含的内容（名称、参赛者、并发、PGN 文件、直播）。菜单可以加载一个模板，或将设置另存为模板（*将设置另存为模板…*，替换同名模板之前会先询问），命令面板也可以加载模板。保存模板时与其配置一致的部分会跟随该配置，因此更新一个配置会更新所有使用它的模板；为那个锦标赛修改过的部分保留它自己的值。早期版本保存的模板按原样加载，它们的各个部分会对应到下法与之相同的配置。名称为空时，会根据引擎生成名称。

### 格式
<!-- en: format 29a36e7c -->

每种格式的工具提示都会说明它是什么。

- *比赛*：两个引擎，A（被测引擎；所有统计数据都从它的角度给出）和 B（基准）。可以是固定的对局数、一直进行直到你停止，或者 SPRT：elo0、elo1、alpha、beta、模型（`normalized` 像 fishtest 和 OpenBench 一样使用 nElo 边界，`logistic` 使用经典 Elo，`bayesian` 使用 BayesElo），以及可选的最大对局数。SPRT 提升和无退步配置给出常用的边界，边界下方的一行文字说明测试大约会持续多少局。*计算器…* 像 fishtest 的 SPRT 计算器一样，根据预期和棋率和开局的 RMS 偏差，绘出 H1 被接受的概率和预期对局数随真实 Elo 差的变化；*使用这些边界*把在计算器中给出的边界复制回设置。*Elo 偏移*（默认 0）加到两个边界上，用于对照一个已知强或弱这么多的版本进行测试：[0, 3] 加上 5 的偏移得到 SPRT [5, 8]，摘要、概览和无界面模式将其写作 `SPRT [0, 3] + 5`；计算器和边界下方的那行文字都会把它考虑在内。*最少对局*（默认 0，即不设）在下满这么多局之前暂缓结论，LLR 仍然照常计算和显示，以防短测试因早期的运气而过早停止：在此之前 LLR 越过边界会在 LLR 条下方注明，比赛继续；对局数达到之后，下一个结束时 LLR 越过边界的对局对会结束比赛。最大对局数低于最少对局数时，比赛结束而没有结论。这是比较一个引擎的两个版本最快的方法，不需要其他任何东西。*颜色*（默认*交替*）决定谁执白：A 和 B 轮流执白，或者 *A 始终执白* 或 *B 始终执白*，与 fastchess 的 `-noswap`（以及 `-reverse`）相同，用于让子棋（较强的引擎必须始终执被让子的一方），或只从一方测试某个开局。对局仍然成对进行，两局颜色相同，但每局都有自己的开局，即开局库中的下一个（与 fastchess 的 `-games 1` 相同）：对局对及其统计数据保持不变，得分包含白方的先手优势，而交换颜色所能抵消的开局 RMS 偏差不再显示。摘要和比赛的标题会说明这一点。
- *循环赛*：每个引擎与其他每个引擎对局*循环数*次，每次交换颜色下两局（即 cutechess 所说的 rounds，每次相遇 2 局）。各轮按 Berger 表编排，因此每个引擎每轮下一次。
- *车轮战*：最前面的*被测引擎*（种子）与其他每个引擎对局，其他引擎之间不对局。
- *瑞士制*：设定*轮数*。每轮是与得分相近的引擎交换颜色下的两局对局；只要能避免，就不会两次遇到同一个对手。引擎数为奇数时，尚未轮空过的排名最低的引擎轮空一次，计 1 分。
- *淘汰赛*：引擎按列表顺序确定种子，参赛人数不是 2 的幂时，排名靠前的种子轮空，前两号种子只可能在决赛中相遇。一场比赛由*每场比赛的对局对数*所设定的若干对对局组成；打平的比赛每次加赛一对，最多加赛十对，之后种子排名较高的一方晋级。
- *团体赛*：两队引擎，用于整体比较一个引擎系列或一组版本与另一个系列或另一组版本。*配对*：*全员交叉对抗*，一队的每个引擎与另一队的每个引擎对局，每轮一个对手（舍维宁根制；两队人数可以不同），或者*逐台对抗*，每队的第一个引擎对另一队的第一个，第二个对第二个，依此类推（两队人数相同）。每组配对进行*循环数*次，每次在同一开局上交换颜色下两局；第一局的颜色在各台之间以及各循环之间交替。*A 队*和 *B 队*为两队命名（不命名时为“A 队”和“B 队”）；旁边显示每队有多少引擎。两队在参赛者列表中组成：列表的上半部分为 A 队，下半部分为 B 队（多出的一个归 A 队），直到把引擎分到某一队为止。

### 参赛者和引擎库
<!-- en: participants-and-the-library a7ef2e55 -->

**参赛者**，旁边是**引擎库**（窗口较窄时在其下方）。每个参赛者占一行：它的位次（车轮战的种子显示一颗星）、名称、参考 Elo、与通用设置不同的下法（“哈希 512 MB · 80 % 的时间”）以及 ⋯，有自己的设置时 ⋯ 会高亮显示。⋯、右键点击或 Menu 键打开这些设置：它自己的 `Hash`、`Threads`、固定节点数或深度、时间让步（时限的百分比，用于棋钟）、它自己的*开局库*、*再加入一次此引擎，使用另一个开局库*、移动操作和*移除*。列表顺序就是种子顺序：拖动参赛者可以重新排序（种子在前），或者按 Ctrl+↑ 或 Ctrl+↓ 将它们移到最前或最后，按 Alt+↑ 或 Alt+↓ 将它们移动一个位置。按住 Ctrl 或 Shift 点击可以选中多个；Delete（或*移除*）移除它们。

在团体赛中，位次是队伍和台次：A 队为 A1、A2…，B 队为 B1、B2…，按列表顺序排列（逐台对抗时，A1 对 B1）。⋯ 菜单把参赛者分到某一队；列表下方的 *A 队*和 *B 队*把选中的参赛者放入其中一队，*按半分队*按列表的上下两半重新组队（命令面板也提供同样的操作）。分好队之后加入的引擎会加入人数较少的一队。摘要会说明每队有多少引擎，如果某队为空，或者在逐台对抗中两队人数不同，开始会被拒绝并说明原因。

引擎库列出未停用的引擎及其参考 Elo，按名称或 Elo 排序（点击列标题），有问题的引擎（程序缺失或已重新构建、上次检查失败：工具提示会说明是哪种）带有 `!`，已经参赛的引擎带有 ✓。筛选框搜索名称、引擎报告的名称、作者、程序、备注和分组（Ctrl+F 让它获得键盘焦点；在其中按 Enter 添加选中的引擎，或显示的第一个引擎）；每个分组有一个标签，点击后只显示该分组，*添加所有显示的*添加整个分组。双击一个引擎，或者按住 Ctrl 或 Shift 选中多个（Ctrl+A：所有显示的引擎）后按 Enter，即可添加它们；也可以把它们拖到参赛者中的某个位置。*建议…* 选中 N 个未停用、可正常工作、参考 Elo 与第一个参赛者（车轮战的被测引擎）最接近的引擎，默认相差最多 150；按 Enter 添加它们。对于比赛，引擎库先填入 A，再填入 B（两者都已选择时替换 B），拖到 A 或 B 上的引擎会取代原来的引擎。

### 参赛者自己的开局库
<!-- en: participants-own-books 580e52cc -->

*开局库*：参赛者自己的开局库，类似 Cute Chess 的 `book=`/`bookdepth=`：开局库页面中的一个 Polyglot（`.bin`）或 PGN 开局库，以及跟随它的深度，以从对局开始计算的半回合数表示，包括锦标赛的开局（*全部*：只要开局库中还有着法；对于 PGN 开局库，为其对局的前 40 个半回合）。PGN 开局库会先转换为 Polyglot 开局库：取每局对局直到该深度的着法，每步着法按走出它的对局数加权；含非法着法的对局会被排除并计数。选择开局库后，转换立即在后台进行（进度显示在*开局库*按钮上、它的弹出窗口中和摘要中），结果保存在配置文件夹的 `book-cache` 文件夹中，直到文件或深度发生变化；在转换完成之前开始的锦标赛会等待它。无法准备的开局库会在其弹出窗口中说明原因，并附有*重试*；每次开始时也会重试。锦标赛使用开始或恢复时准备好的开局库，即使 PGN 文件在此期间发生了变化。

只要局面还在该开局库中，参赛者就立即走出开局库的着法，按开局库的权重并经开局的*随机度*调整后选择（随机度也在*开局库*弹出窗口中，对锦标赛的所有开局库都相同：见[开局](#开局)）；之后由它的引擎接手。锦标赛的开局（如果有）会先由每个引擎下完；EPD 开局库只能提供这类开局，因此在列表中显示为灰色。要用一个引擎比较多个开局库，可以在它的 ⋯ 菜单中选择*再加入一次此引擎，使用另一个开局库*：每个副本以 `<engine> (<book>)` 的名称参赛，因此它们的成绩和等级分各自独立。在比赛中，*开局库*按钮位于 A 和 B 旁边，一个引擎可以用两个开局库与自己对局。开局库着法在 PGN 中标记为 `{book}`；在排名中将鼠标悬停在名称上会显示它的开局库。WinBoard 引擎也可以有自己的开局库。

### 引擎设置
<!-- en: engine-settings 7a93d075 -->

*Hash* 和*线程*强制用于每个引擎，比赛也一样（0 = 每个引擎自己的值；参赛者通过 ⋯ 菜单设置的值优先）；*为引擎提供 Syzygy 残局库*把残局库目录（与裁定所用的相同）提供给每个带有 `SyzygyPath` 选项的引擎，*关闭引擎自带开局库*在存在 `OwnBook` 选项的引擎上将其设为 false，使每局对局都从锦标赛的开局开始。两者默认都关闭。

### 时限
<!-- en: time-control 672cb041 -->

以秒计的基本时间和加秒、可选的每个时段的步数，以及判超时负之前的余量；固定的每步时间（`go movetime`，使用同样的余量）；固定的每步节点数；或者以半回合计的固定深度（`go depth`），这种方式下没有引擎会超时判负。

### 并发
<!-- en: concurrency c02ee2cf -->

同时进行的对局数。在自动模式下，它在启动时测定：

- 固定节点数或深度：每个硬件线程一局，因为超线程不会改变走出的着法；
- 使用棋钟：物理核心数 − 1，使引擎之间不会互相拖慢。

该行以及输入框下方的那行文字会说明这个数是按哪条规则选出的。*CPU 亲和性*（默认关闭；macOS 不支持亲和性，因此没有此项）把每局对局绑定到一个处理器上，由该局的两个引擎共用，因为它们从不同时思考。fastchess 只对单线程引擎支持它，因此当某个引擎的 `Threads` > 1 时会自动关闭。当并发数 × 线程数超过硬件线程数（或者使用棋钟时，超过物理核心数）时，会出现警告。*运行于*选择锦标赛在哪台机器上进行（见[在机器上运行锦标赛](#在机器上运行锦标赛)）。

### 开局
<!-- en: openings 44656411 -->

一个 EPD、PGN 或 Polyglot（`.bin`）开局库（开局集），随机或顺序排列，从 PGN 开局库中保留的半回合数，起始序号和随机种子（0 = 每个锦标赛使用新的顺序）。每个开局都交换颜色下两次（在*颜色*固定的比赛中，每局各用自己的开局）。

Polyglot 开局库从初始局面开始跟随到一定深度（未设置时为 8 个半回合），并排除权重不到其局面中最佳着法十分之一的着法；到达的局面一次性写入锦标赛文件夹中的 `<book>-<N>plies.epd`，然后像 EPD 开局库一样使用。按随机顺序时，局面按抽取的顺序写入，每个局面一次：按其着法的权重，一条变化的可能性越大就越靠前，因此只下开局库一部分的锦标赛会先下其主要变化；同一个种子会再次抽出相同的顺序。按顺序排列时，局面保持开局库中的顺序。*随机度*（−100 到 100，默认 0）决定权重如何计算，与 Polyglot 和 Cute Chess 选择开局库着法的方式相同：0 表示按原权重，−100 表示只取每个局面的最佳着法（只有一条变化，除非有多个着法共享最高权重），100 表示所有着法机会均等（罕见着法也会出现）；介于两者之间时，−50 将权重平方，50 取权重的平方根。它同样用于选择参赛者自己的开局库中的着法，即使锦标赛使用 EPD 或 PGN 开局库，也会为参赛者的开局库显示它；摘要会说明它，复制的排名下方的那一行会给出开局库及其深度，对于 Polyglot 开局库还会给出这个随机度。

在循环赛、车轮战、瑞士制或团体赛中，*同一轮中所有对局对使用同一开局*让同一轮中的每一对对局都使用同一个开局（逐台对抗时，一个循环就是一轮：每一台都下同一个开局），每轮取开局库中的下一个开局，因此同一轮中没有引擎会得到比其他引擎更容易的开局（后来加入的引擎在它自己的补赛轮次中赶上进度，每轮有各自的开局）。

*标记失衡的开局*（默认关闭）随着对局的进行显示那些本身就决定了胜负的开局：如果在出库后的前几步（默认 4 步；参赛者自己的开局库着法算作开局库着法）中，两个引擎每一步都认为同一方至少领先该分数（默认 200 cp），该对局会在结束时被标记。它读取引擎的评分，因此不给出评分的引擎不会标记任何对局；结果不会被改变。*对局*标签页可以筛选这类对局（*失衡的开局*），*开局*标签页用 `!` 标记它们的开局并计数，概览统计这类对局的数量。*用另一个开局重下这一对*会在这样的一对对局的两局都下完后将其作废（它们和任何作废的对局一样，保留在 PGN 文件和日志中），并用开局库末尾（按开局库的使用顺序）的一个开局重下，这个开局本来是锦标赛最后才会下的，这样后面各对对局的开局不会移动；一对对局最多重下三次，之后这一对计入成绩，并带有标记。控制台和概览会说明替换了多少个开局。

### Chess960
<!-- en: chess960 515f3f2d -->

Fischer 任意制象棋，在开局中设置：没有开局库时，使用随机顺序的 960 种初始局面（一次性写入锦标赛文件夹中的 `chess960.epd`）；有开局库时，使用开局库中的局面。每个引擎都必须支持 Chess960：UCI 引擎需要 `UCI_Chess960` 选项，WinBoard 引擎需要 `fischerandom` 变体。摘要会指出不支持的引擎，这样的锦标赛不会开始。

### 裁定
<!-- en: adjudication a18dca1e -->

和棋（从某一步起，连续 N 步评分低于某个值）、认输（连续 N 步评分高于某个值，可选要求双方引擎一致）、最大步数，以及 Syzygy 残局库。

### PGN 及其他
<!-- en: pgn-and-misc 6762bab8 -->

- 赛事名称：它的工具提示指出每局对局写入的两个 PGN 文件。
- *同时把每局对局追加到*：你自己的一个 PGN 文件，每个锦标赛都会把它的对局追加到其中，类似 cutechess 的 `-pgnout`（从不覆盖，使用 ChessBase / Lichess 或 cutechess 的注释格式），按赛程顺序排列：一个开局的两局对局相邻，各轮按顺序排列，不论它们以什么顺序结束。一局对局会在那里等待，直到它之前的对局都已写入；恢复锦标赛时会继续写入；当文件无法写入时（被锁定、被移动），对局会等待，锦标赛继续进行，并在概览中显示警告。追加对局时发生崩溃或断电，也绝不会重复写入：恢复时会检查文件，补全被中断的写入，并且从不删除其中的任何内容。
- 着法注释中的额外字段（nodes、seldepth、nps、pv、tbhits，以及决定时间 `dt=`：引擎确定它所走着法的时刻；对于报告 `wdl=W/D/L` 的引擎，总是会写入它），默认开启，因为*对局*标签页的图表要读取它们（pv 会让 PGN 明显变大）。
- *重启崩溃的引擎*，以及*引擎无法启动时停止锦标赛*（默认关闭：见[无法启动的引擎](#无法启动的引擎)）。
- 保存每局对局的引擎日志（异常结束的对局总是会保存）。
- *检查将杀 PV*：将杀评分的 PV 必须长度正确并以将杀结束。每条 PV 都会被检查是否有非法着法、对局结束之后的着法，以及最佳着法不是其第一步的情况；带有错误 PV 的着法会在对局标签页中标出，并写入日志。

### 设置建议
<!-- en: tips-for-the-settings 62afdb4d -->

- **比较一个引擎的两个版本**：使用 SPRT，对旨在提升棋力的改动使用提升 [0, 3]，对简化或代码清理使用无退步 [-5, 0]。先用短时限（10+0.1），通过的再用长时限（60+0.6）测试。使用由均衡局面组成的开局库，而不是初始局面：否则每局对局都只会是少数几种开局之一。
- **并发**：保持自动。使用棋钟时，对局数超过物理核心数减一会让引擎互相拖慢，结果会出现偏差；按每步节点数或深度时，每个硬件线程都可以下一局。
- **线程**：测试时每个引擎 1 个线程；许多单线程的对局比少数多线程的对局每小时能产生更多结果。在*引擎设置*中给每个引擎设置相同的 `Threads` 和 `Hash`。
- **Hash**：够当前时限使用即可（10+0.1 时 16 到 64 MB，40/15 及更长时 256 MB）；当对局的哈希表已放不进内存时，摘要会提示。
- **裁定**：标准配置在长时间的锦标赛中可以节省时间，而且对结果影响不大；要测试引擎的残局，请关闭裁定，或者使用残局库。
- **开局**：使用固定种子的随机顺序，可以让测试完全重现；在循环次数少的循环赛中，*同一轮中所有对局对使用同一开局*更公平。
- **多个锦标赛**：给最重要的那个锦标赛更大的权重，而不是暂停其他锦标赛（见[同时进行多个锦标赛](#同时进行多个锦标赛)）。

## 运行锦标赛
<!-- en: running-a-tournament 9bcba803 -->

正在进行或已打开的锦标赛有一个工作区，包括页眉（名称、进度、*暂停*、*停止*、*克隆*、*文件夹*、*布局*）和若干面板，面板默认以标签页的形式显示：

| 标签页 | 显示内容 |
|---|---|
| 概览 | 目前为止的结果和统计、图表、提交检查清单 |
| 排名 | 表格或交叉表形式的排名、某个引擎的对手、用于论坛的复制内容 |
| 各队 | 团体赛：各队的比分以及两队之间的交叉表 |
| 对阵表 | 淘汰赛：逐轮的对阵表 |
| 赛程 | 每一对对局，以及对锦标赛所做的修改 |
| 直播 | 实时文件、TLCS 服务器、网页和 lichess |
| 实时 | 正在进行的对局 |
| 对局 | 已结束的对局、它们的筛选、回放和导出 |
| 开局 | 按起始局面统计的结果 |

### 概览
<!-- en: overview 6985cebb -->

**比赛**：Elo 和 nElo 及其 95% 置信区间、LOS、得分、五项分布计数、SPRT 边界和 LLR。*统计*（默认折叠）给出 fishtest 根据单局和根据对局对计算的各项数值：得分、Elo、nElo 以及 BayesElo 和 DrawElo、每局的标准差、两种方式的 LLR、对局对与单局的方差比、开局的 RMS 偏差、均衡对局对的类型，以及胜 / 负对局对，*复制*会包含这些内容。然后是图表：Elo 和 LLR 随时间的变化、对局长度、对局的结束方式，以及*各引擎的搜索*。

**锦标赛**：排名（含 *TF*，即每个引擎的超时判负次数，一旦出现就显示为橙色；崩溃过或走过非法着法的引擎旁有一个 *!*），排名下方的*各引擎的搜索*，按循环或轮次的进度、每小时对局数和剩余时间、最新的结果。

*各引擎的搜索*给出每个引擎在它搜索过的着法上的平均值（不计开局库着法）：深度、NPS、每步时间、决定时间和处理器占用；点击某一列即按该列排序引擎。NPS 旁的 ×4 表示该引擎用 4 个线程搜索：它统计的节点比单线程多，但并不因此更快，所以请把它的 NPS 与线程数相同的引擎比较。NPS 需要引擎自己报告，并且要勾选 *PGN 及其他*中的 *nps*，继续锦标赛时才能读回。

当设置中开启了失衡开局检测时，两者都会统计来自失衡开局的对局以及被替换的开局，并附有*显示*这些对局的按钮。已结束的锦标赛还会增加一份*提交检查清单*：所有对局都已下完、每一对都交换过颜色、没有重复的对局、没有崩溃、超时判负或非法着法（附有打开这些对局的按钮）、每个引擎的 Hash（只显示，不评判）、ponder 已关闭、开局库、残局库。

### 排名
<!-- en: standings e4198fcd -->

积分、对局数、超时判负（*TF*）、胜/和/负、等级分及其置信区间、Sonneborn-Berger（瑞士制为 Buchholz）、轮空。*表格*每行列出一个引擎；*交叉表*（循环赛，最多 200 个引擎）显示每一组配对。*排序*：按积分、得分率或种子顺序（种子顺序让车轮战交叉表的列保持不动）。点击一个引擎会在下方列出它的对手：对局数、执白、执黑、+ = −、积分和百分比，只下了一局的对局对会被标出；车轮战打开时会选中其种子。

*复制*可以复制为文本，或复制为用于论坛帖子的 BBCode（附有一行说明格式、时限、对局数和开局库的文字），在车轮战中还有*车轮战表格（文本）* 或 *BBCode 格式，用于论坛*（先是种子，然后是按各自积分排列的对手，每个都带有积分、百分比、Elo ±、W-L-D）；还有*导出 HTML…*。所有这些都与无界面模式的排名一样包含 *TF*，遵循所选的排序，并以一行文字结尾，给出计划对局中已下的对局数、和棋率、时限、开局库（PGN 开局库附保留的半回合数；Polyglot 开局库附其深度及着法的选择方式，例如 `book:Perfect2023.bin (8
plies, moves by weight)`）和赛事。复制的内容随后以 *fastchess-gui* 及其版本号署名，车轮战表格用 = 而不是 - 画线，这样贴到论坛上的表格可以与其他程序的表格区分开来。

### 各队
<!-- en: teams 8c845645 -->

仅用于团体赛，显示在*排名*标签页中（团体赛打开时显示该标签页）和*概览*的顶部：两队的比分，例如“Lynx 17½ – 18½ Otter”，附有已下的对局数、A 队的得分率、该得分率所对应的 Elo 差及其 95% 区间和 LOS，与比赛的统计一样按对局对计算（五项分布）；然后是每队的引擎，附有对局数、积分、百分比、等级分，以及每个引擎对另一队每个引擎的得分（B1、B2… 作为列，鼠标悬停时显示名称）：即两队之间的交叉表。*表格*和*交叉表*像在任何锦标赛中一样显示各引擎。*复制*和*导出 HTML…* 给出两队的比分和两队引擎之间的对阵结果，以及其下方的那一行。

### 对阵表和赛程
<!-- en: bracket-and-schedule fe207ac0 -->

*对阵表*，仅用于淘汰赛：逐轮的对阵表，附有每场比赛的比分。*赛程*：按循环或轮次列出每一对对局，附有其状态和所下的开局（开始之后才显示；如果同一轮共用一个开局，则在该轮开始之后显示），以及对锦标赛所做的修改（见[修改进行中的锦标赛](#修改进行中的锦标赛)）。

### 实时
<!-- en: live 5561ed9b -->

正在进行的对局，以棋盘平铺的形式显示，或者聚焦显示一局对局，附有棋钟、每个引擎正在进行的搜索（深度、评分、节点数、nps、SAN 格式的 PV）、着法列表和对局图表（见[对局图表](#对局图表)）：图表显示两个引擎的评估，在其各个标签页中还可以显示它们的胜率、每步时间及决定时间、深度及 seldepth、节点数、速度、残局库命中数、两者的评估相差多少，或者一个引擎的 PV 有多少个半回合与另一个引擎的 PV 所预测的相符。胜/和/负的比例（`UCI_ShowWDL`，引擎添加时如有此选项会自动开启）跟在每条搜索信息后面；*胜/和/负*标签页以色带的形式绘制它们，白方胜的比例在最下面。

空间足够时（聚焦显示一局对局，或面板较大），每个引擎有一张卡片：标志与名称和棋钟一样高，显示它在做什么（正在思考，或它走的着法），逐项显示它的搜索（深度和 seldepth、评分、节点数、速度、引擎发送时的残局库命中数和哈希占用率、到目前为止在这步棋上用的时间）以及它的完整 PV；等待中的引擎显示它走棋时的输出，以及它作出决定的时刻。在平铺视图旁边，面板保留一行数字和 PV 的前 12 个半回合。标签页右侧的*走棋方视角评分* | *白方视角评分*决定其中所有评分的视角：走棋方视角（fastchess 写入 PGN 的方式），或白方视角；评估条和大屏幕始终按白方视角。

着法上方：开局，即命名开局表中所收录的本局最深局面的 ECO 代码和名称（开局库着法和引擎着法一视同仁，因此开局库之后的变着转换也会得到名称），并注明开局库的最后一步；当锦标赛的 Syzygy 残局库（其裁定所用的残局库，否则为提供给引擎的残局库）收录所显示的局面时，显示其结论：获胜的一方及 DTZ（距下一次吃子或兵步的半回合数：Syzygy 残局库没有距将杀的步数），或和棋；五十步规则按本局自身的计数计算，除非裁定设置忽略此规则。每个局面只查询一次，在下棋的线程之外进行。在列表中，每步引擎着法都附有评分、深度和用时；鼠标悬停时还会显示引擎作出决定的时刻以及它预期的应着（其 PV 的第二步：fastchess 下棋时不使用后台思考）。开局库着法标为*开局库*，一行标出开局库的结束，正在思考的着法标为*思考中*。

平铺视图为每局正在进行的对局显示一个棋盘，而不是为并发允许的每局对局显示一个：在锦标赛接近结束时，或者对局数少于并发数时，剩下的棋盘会变大。对局已结束的棋盘会保留 10 秒（其槽位的下一局对局会在那里开始），正在关注的对局的棋盘会保留；当没有对局在进行时，保留最后几局对局。当棋盘需要滚动条时，平铺视图会从聚焦的对局那里借用宽度，直到聚焦对局只占页面的 40%。

棋盘下方：50 步计数（自上次吃子或兵走动以来的半回合数，满 100 为止）、子力差及一方多出的棋子，以及剩余的棋子，当残局库裁定可以结束对局时标记为 *TB*；*在棋盘下方显示详情*把这些信息也加到平铺视图中。再往下是浏览着法的按钮（见[棋盘及其按钮](#棋盘及其按钮)）：聚焦的对局或分离的棋盘可以在对局进行时往回翻（也可以用 ← → Home End，或点击列表中的着法或曲线），显示之前的局面，并在列表和曲线上标出其着法；*回到当前着法*（或 End，或点击最后一步）让它重新跟随对局，每开始一局新对局时也会如此。

*箭头*（默认开启）在聚焦的棋盘和分离的棋盘（不包括平铺视图）显示当前着法时，以走棋方引擎的颜色绘出它正在考虑的着法，并以对手的颜色较浅地绘出它预期的应着。在车轮战中，*被测引擎在下方*（默认开启）从种子一方显示每局新对局；翻转棋盘（F 或其按钮）仍然有效，直到下一局为止。*分离*在独立的窗口中打开一个棋盘。在棋盘上点击右键可以以某个结果结束其对局（见[修改进行中的锦标赛](#修改进行中的锦标赛)）。*大屏幕*让所关注的对局占满窗口（见[大屏幕](#大屏幕)）。

### 大屏幕
<!-- en: big-screen 14c8f0d6 -->

*大屏幕*（在*实时*标签页中、分离的棋盘上，或在命令面板中）用于电视、俱乐部或直播，让一局对局占满窗口，黑底浅色字：棋手的名称和棋钟以大字显示（走棋方及其正在走的棋钟为黄色，不到十秒的棋钟为红色），评估条，搜索的评估、深度和速度，上一步在棋盘上加框并以大字写出，开局，引擎的变化（*变化*，默认开启：走棋方为其搜索中的变化，以黄色显示，另一方为其上一步时的变化，每条最多两行），残局库收录该局面后的结论，着法以大字显示，最后一步带有标记；对局结束后，结果显示在棋盘上方。文字大小随窗口大小变化，并且可以单独调整（*A-* / *A+*，或 + 和 - 键）。它显示所关注的对局，或者每隔 N 秒在正在进行的对局之间切换（*轮流显示每局对局*），或者跟随*最有看点的*对局：最接近均势的对局，同样接近时取最长的一局，只要它保持如此就一直显示。移动鼠标时控件显示三秒（鼠标指针随控件一起隐藏）；← 和 → 切换对局，F11 使窗口全屏，Esc 退出。移到另一块屏幕（电视）上的分离棋盘会在它自己的窗口中显示大屏幕，F11 让该窗口全屏，而主窗口照常工作；停靠在主窗口中时，由主窗口显示大屏幕。

### 对局
<!-- en: games ba4a9604 -->

已结束的对局及其开局（ECO 代码和名称），以及一个回放棋盘：使用其下方的按钮、← → Home End 和 F，或点击着法或图表；棋盘下方有与*实时*中相同的详情和相同的对局图表（见[对局图表](#对局图表)），数据来自 PGN 写入时所含的字段：如果锦标赛没有写入某个图表所需的字段，该图表会以灰色列在图表的 `⋯` 菜单中，并说明这一点，附有一个转到设置中 PGN 选项的按钮。

**筛选**：按结果（胜、和、负、超时判负、崩溃和非法着法、裁定、错误的 PV，以及当设置开启检测时，开局被标记为失衡的对局）；按评估反映的情况（引擎意见分歧，双方评估相差 N 个兵并各自连续保持 3 步；某个引擎的评估在其相邻两步之间变化 N 个兵；输家曾认为自己领先 N 个兵；对局会在该时刻打开）；以及按开局（ECO 代码或其开头、`B20-B99` 这样的范围，或名称中的词）。

**导出**一局、全部或筛选出的对局：*全部导出…* 建议在锦标赛文件夹旁边保存为 `<name>.pgn`；不能以锦标赛自己的 PGN 文件作为导出目标。*导出给等级分列表…* 按等级分列表测试者（例如 CCRL）提交的方式写出对局：`[Tester YYYY-MM-DD] Event (hash NMB) (book X) (egtb N-man).pgn`，如有需要还会生成 zip；棋手按等级分列表的写法命名，`<engine> 64-bit 4CPU`（可为每个参赛者编辑），轮次重新编号，设置 `Event` 和 `Site` 标签，去除作废的对局和重复的对局，除非取消勾选，因崩溃或卡住而输掉的对局也会去除；因非法着法而输掉的对局，其 `PlyCount` 只计算写出的着法。测试者和地点会被记住。

*引擎日志*打开有日志的对局的日志（见[文件](#文件)）。在对局上点击右键可以重下、作废或设定其结果（见[修改进行中的锦标赛](#修改进行中的锦标赛)）。

### 开局标签页
<!-- en: the-openings-tab c51dd29a -->

按起始局面统计的结果：它的对局对数、白方得分、和棋数，以及白方两局皆胜（该开局偏向某一颜色）、黑方两局皆胜或同一引擎两局皆胜（该开局能区分引擎强弱）的对局对数，以及平均长度。可以按任意一列排序，筛选出失衡的、和棋的或分出胜负的开局，或者筛选出*对局中被标记为失衡*的开局（见设置中的[开局](#开局)：标记为 `!`，其数量显示在计数旁边，并附有被替换的开局）。*导出为 EPD…* 写出显示的局面，用于保存或清理开局库，*不含失衡的*（默认开启，有开局被标记后才显示）会排除被标记的开局。点击会显示该局面及其对局。在*颜色*固定的比赛中，每局都有自己的开局：统计的是对局数，与对局对有关的列和筛选不再显示。

### 面板和布局
<!-- en: panels-and-layouts 9ed9b915 -->

每个标签页都是一个面板。拖动面板的标签，可以把它停靠在另一个面板的一侧，或作为标签页放在它旁边，也可以放到别处让它浮动（在 Windows 和 Linux/X11 上还可以拖到第二块屏幕上，Wayland 下或使用软件渲染时不行）。*实时*中所关注的对局可以拆分为*棋盘*、*棋手*、*搜索*、*着法*和*图表*面板；没有打开面板的部分留在*实时*中的平铺视图旁边，分离的棋盘可以像其他面板一样停靠。点击面板标签上的 x 关闭面板；通过*布局* > *面板*或命令面板中的*显示 …* 恢复面板，恢复后它处于停靠状态。

*布局*还提供现成的布局（*标签页*，即默认布局；*关注一局对局*：棋盘在左侧，棋手、搜索和图表在右侧，排名在它们下方；*大型锦标赛*：平铺视图在排名旁边；*直播*：一个大棋盘，附有棋手、搜索和排名）、*将布局另存为…*（你自己的布局，按名称保存在配置文件夹的 `layouts.json` 中）、*删除*和*默认布局*。从工作区中拖出的面板在其他页面上仍留在屏幕上；面板的排列在不同会话之间保留。

### 处理器占用
<!-- en: processor-use e5234cbe -->

对局进行时，每个引擎的进程（包括 WinBoard 适配器背后的引擎）所占用的处理器时间会在每次 `go` 和每步着法时测量。概览为每个引擎显示它思考时占用的核心数，以及对手思考时它占用的单个核心的比例；当某个引擎占用的核心明显多于它的 `Threads`，或者在对手的时间里思考（未被要求的 ponder、后台线程）时，会发出警告：这些情况会让对局对对手和同时进行的其他对局不公平。它需要各 20 秒的数据才能判断，并统计每一局已下的对局，无论是在窗口中还是在无界面模式（`--run`）下：每局对局的引擎占用的资源会写入锦标赛文件夹中的 `processor.tsv`，因此恢复时会保留。它只发出警告，从不判定对局。

### 暂停、停止和继续
<!-- en: pause-stop-and-resume 100c55cf -->

**暂停**后不再开始新的对局对。进行中的对局会下完，第一局已经开始的对局对的第二局也会下完，因此暂停永远不会丢弃结果。**继续**恢复进行。**停止**可以先下完进行中的对局，也可以立即停止（被中断的对局不计入，之后会重下）。

因引擎而停止的锦标赛会在页眉和主页的*需要处理*下指出是哪个引擎：*已中断：Alpha 无法启动：…*（在最后一次尝试之后），或者 *Alpha 崩溃或无响应（第 12 局）*（未开启*重启崩溃的引擎*时），附有*打开引擎*和*打开日志*。

**每个锦标赛都会从中断处准确继续**，无论是停止、关闭窗口、崩溃还是断电之后：不会丢失对局，也不会重复下同一局，下了一半的对局对会用相同的开局和颜色补全。主页上的*继续*会继续该锦标赛，并带有已下对局的统计数据：结果，以及从着法注释中读回的引擎深度、每步时间和 NPS（只有当 PGN 记录了 NPS 时才有，即 *PGN 及其他*中的 *nps*）。如果程序在锦标赛进行时结束（崩溃、断电、重启，或在锦标赛进行时退出），下次启动时会自动恢复它，之后队列继续：这是**设置**中的*启动时恢复之前正在进行的锦标赛*，默认开启。已暂停或已停止的锦标赛会等待你操作，而 `--autostart` 改为开始已保存的设置。如果某个参赛者的程序在其加入后被重新构建或已丢失，恢复的锦标赛会在页眉中指出它，并附有*继续*和*暂停*：它接下来的对局由程序的当前版本来下，使用锦标赛给它的选项。

### 同时进行多个锦标赛
<!-- en: several-tournaments-at-once df7ce566 -->

多个锦标赛可以同时进行：一个车轮战与一个 SPRT 同时进行，或者同时进行两个车轮战。在已有锦标赛进行时，*新建锦标赛*页面上的*开始*会再开始一个锦标赛；*继续*会在它们旁边恢复一个锦标赛。每个锦标赛都在各自独立的进程中进行（由窗口驱动的 `fastchess-gui --run <folder>`），因此崩溃只会让那个锦标赛停下，而窗口及其引擎检查、快速测试和测试集也不再需要等待锦标赛结束。

工作区在页眉上方**为每个打开的锦标赛提供一个标签页**：进行中时显示一个圆点（暂停时显示暂停符号），鼠标悬停时显示其状态，不在进行中的锦标赛有一个关闭用的叉号。各面板显示所选的标签页；命令面板列出其他锦标赛（*显示 …*、*暂停*、*继续*）。从列表中打开已结束的锦标赛时，它会占用某个仅在查看、并未进行的锦标赛的标签页。主页为每个进行中的锦标赛提供一张卡片，附有其进度、领先者、*打开*和*暂停*，下面是它的**权重**、它的对局在可用核心中占用的核心数，以及它的下一局在等待什么；顶部的*核心*条显示每个锦标赛（以及棋盘页面）所占的部分，以及各锦标赛共享多少个核心。*日志*显示某个锦标赛的日志行、窗口自身的日志行，或者全部（锦标赛的每一行都带有其名称）；锦标赛的日志行也保存在其文件夹中的 `fastchess-gui.log` 里。

**共享本机**：进行中的锦标赛共享一个核心预算，在**设置**中设定（*锦标赛使用的核心*：默认为物理核心数减一）。只要预算允许，每个锦标赛先得到够下一局的核心，权重最大的优先；其余的按权重分配（权重为 2 的锦标赛得到的核心是权重为 1 的两倍），均不超过其自身的并发数，一个锦标赛用不了的部分分给其他锦标赛。一局对局按其两个引擎中较大的 `Threads` 计算：一个引擎思考时另一个在等待。暂停的锦标赛只保留其进行中的对局及这些对局所在对局对的第二局所需的核心。份额减少永远不会中断对局：锦标赛从下一局开始减少同时进行的对局数。单独进行的锦标赛按其并发数下棋。

**内存**：只有当一局的两个引擎的 `Hash`，加上每个引擎进程额外占用的内存（64 MB，每线程再加 8 MB），能放进进行中的对局在内存预算中剩下的部分时，这局才会开始（内存预算即**设置**中的*引擎使用的内存*，默认为已安装内存的 75%），该预算由各锦标赛共享。设置的摘要会说明预算允许同时进行多少局，主页的*稳定性*卡片会在对局等待内存时提示。

**GPU**：信息卡上标记为*使用 GPU* 的引擎（例如 Lc0 这样的神经网络引擎）计入**设置**中的 *GPU* 数：同时下棋的此类引擎不会多于 GPU 数，在一个锦标赛内和各锦标赛之间都是如此，其他对局则在它们旁边同时进行。设置的摘要会说明这允许同时进行多少局含 GPU 引擎的对局，并在没有计入任何 GPU 时，或者两个 GPU 引擎之间的对局需要的 GPU 多于本机拥有的数量时发出警告（这时该对局会单独进行）。

**保持运行**：在锦标赛进行时关闭窗口，会询问如何处理。*让它们继续并退出*（默认）让每个锦标赛在各自的进程中继续进行；窗口下次启动时会按它们当时的状态重新显示它们。*停止并退出*会停止它们，每个锦标赛之后都可以从中断处准确继续。无论哪种方式，快速测试都会停止。如果到下次启动时某个锦标赛的进程已不存在（重启、崩溃），它会像任何被中断的锦标赛一样恢复。*直播*标签页的直播在窗口中运行，针对显示的锦标赛：如果希望直播在没有窗口时继续，请在终端中带上直播选项开始锦标赛（见[无界面模式](#无界面模式)）。

### 无法启动的引擎
<!-- en: an-engine-that-cannot-start 765a7c61 -->

无人值守的一整夜不会因为一个引擎而停下。无法启动的引擎（程序被移动或重新构建、网络文件缺失、磁盘不见了）会再尝试三次，每次间隔 10 秒；之后它的对局会被搁置，其他对局继续。此后每 5 分钟再尝试一次，每次一局，一旦它能启动，它的对局就会恢复。锦标赛的页眉和主页（在*需要处理*下）会指出是哪个引擎、错误信息，并提供：

- **重试**：立即重试，而不是等到下一次尝试（例如在修复程序之后）。
- **退赛…** 和**替换…**（循环赛、车轮战和团体赛）：赛程标签页的修改面板，已针对该引擎设置好，在做任何修改之前会显示其影响。
- **引擎日志**：锦标赛文件夹中的 `logs/start-<engine>.log`，即最后一次尝试时发送给引擎的内容以及引擎的回应，包括其错误输出（原因常常就在这里：找不到某个库或网络文件）。

日志和桌面通知会说明何时搁置了某个引擎。只有在除被搁置的引擎之外已没有可下的对局时，并且在对每个引擎做了最后一次尝试之后，锦标赛才会停止；它的状态和结束时的通知会说明这一点（*已停止：没有无法启动的 … 就没有可下的对局了*），队列会继续下一个锦标赛。*继续*会重新尝试每个引擎。暂停会搁置这些尝试。设置的 *PGN 及其他*中的*引擎无法启动时停止锦标赛*则会在尝试次数用完后立即停止锦标赛。

### 修改进行中的锦标赛
<!-- en: changing-a-running-tournament aebe63e2 -->

*赛程*标签页中的**修改锦标赛**面板无需停止任何东西即可工作：进行中的对局继续，已下的对局不会丢失。每项修改在应用之前都会显示其影响。

- **添加引擎**：它补下已经开始的循环（*补齐已经开始的循环*），或者从下一个循环开始加入。
- **让一个引擎退赛**：它剩余的对局被取消；它已下的对局可以计入，也可以不计入。
- **替换引擎**：它的对局不再计分，由新引擎重下。
- **循环数**：增加或减少。
- **重下对局**：某个引擎的每一局对局，或者超时判负和崩溃的对局。
- 在对局上点击右键（在这里，或在*对局*标签页中）：重下、作废（不重下）或设定其结果。

添加的引擎或替换上场的引擎使用锦标赛的设置（时限、Hash 和线程，显示在引擎下方），或者使用*自己的设置*：Hash、线程、时间份额（或节点、深度），与*新建锦标赛*页面上参赛者自己的设置相同。0.6.6 之前创建的锦标赛没有记录自己的设置：由它的第一个引擎的设置代替，而那可能是该引擎自己的设置。

在团体赛中，添加的引擎加入所选的队伍，并与另一队的每个引擎对局；逐台对抗时不能添加引擎（它的台次没有对手）：请改为替换一个引擎。替换者继承被替换引擎的队伍和台次；增加的循环为仍在参赛的引擎配对（逐台对抗时，按第一个循环的台次）。退赛或被替换的引擎已下的对局仍计入其所在队伍，除非它们被作废。

**设定结果**用于判定程序未能正确判定的对局：未被发现的卡死、引擎在必胜残局中来回走子、因错误原因结束的对局。选择 1-0、½-½ 或 0-1 并给出原因；在*设定结果*应用之前，会显示它改变的积分。排名、交叉表、等级分和提交检查清单都会计入新的结果（相当于一次裁定：被改为和棋的超时判负不再计为超时判负）；*对局*标签页用 `*` 标记它，其工具提示给出原因以及对局实际的结束方式，*恢复实际下出的结果*可以撤回。正在进行的对局也可以用同样的方式结束：在*实时*标签页中右键点击它的棋盘，选择*以指定结果结束*（对于所关注的对局，命令面板中也有）。轮到走棋的引擎会被停止，fastchess 立即结束对局，并以所选的结果计分；该引擎会为下一局重新启动。这需要开启*重启崩溃的引擎*（设置，*PGN 及其他*，默认开启）。

作废的对局和手动设定的结果在 PGN 文件和日志中保持实际下出的样子：PGN 文件只会被追加。读取对局的功能会应用它们：作废的对局会被排除，手动设定的结果会出现在每一种导出中（*导出对局…*、*全部导出…*、*导出给等级分列表…*、*等级分*页面的交手记录导出、*同时把每局对局追加到*的文件），带有 `[Termination "adjudicated by the operator"]`，原因写在结果之前的注释中。**撤销上一次修改**在下一局开始之前都可以使用：在这次修改之下还没有下过任何对局，因此可以准确撤回（修改时已经在进行的对局会保留）。手动设定的结果只要是最后一次修改，无论之后是否下过对局，都可以撤销（在淘汰赛中，后续轮次取决于结果，因此只能在下一局开始之前撤销）；*对局*标签页也在该对局旁边提供*撤销*。

### 队列与重新开始
<!-- en: queue-and-relaunch 382fd33e -->

主页上的**队列**保存要依次进行的锦标赛：一个锦标赛自行结束时，下一个开始（停止或出错之后不会，*全部暂停*挂起队列时也不会）。开启*有空闲核心时启动*后，一旦核心预算多于正在进行的锦标赛按各自并发数所能占用的核心，下一个锦标赛就会与它们同时开始。队列中的锦标赛可以重新排序或移除，没有锦标赛在进行时，可以立即开始第一个。主页会显示当前锦标赛的预计结束时间（*预计 HH:MM 结束（还需 …）*）以及整个队列的结束时间，每个排队的锦标赛都显示其时长，并且在它之前的锦标赛时长都已知时，显示它的开始时间；无法得知时长的锦标赛（没有上限的 SPRT、按每步节点数或深度的锦标赛）单独计数。

已结束比赛上的**重新开始，使用…**（在它的页眉中，或主页的*最近完成*下）用另一个引擎 A（通常是下一个版本）对同一个引擎 B 重新进行比赛，其他设置沿用该比赛的设置（对于由不保存设置的旧版本启动的比赛，则取自*新建锦标赛*页面）。

**克隆**（在锦标赛的页眉中，以及主页的*最近完成*和*所有锦标赛*中）打开*新建锦标赛*页面，并填入该锦标赛的设置，无论其格式如何：参赛者及其各自的设置、时限、开局、裁定以及其余一切，每个值都与当时下棋时一致。它的配置会显示名称，之后修改过的配置会标记为仅对本锦标赛做了修改。改动需要不同的地方（换一个时限、换成某个引擎的下一个版本、换一本开局库），然后点击**开始**或*加入队列*。仍在进行的锦标赛也可以克隆；由不保存设置的旧版本启动的锦标赛则不能克隆。

## 等级分
<!-- en: ratings 3e4be48f -->

**等级分**页面基于配置文件夹中所有锦标赛的所有对局以及导入的 PGN 文件，计算最大似然等级分（logistic 模型，和棋计半分，与 Ordo 的默认做法相同）。引擎按名称识别。计入的对局可以在页面顶部缩小范围，对所有标签页有效：

- 时限、引擎库中的一个分组（该分组内引擎之间的对局）、最近 30 天或 365 天；
- *已导入的对局*：*PGN 文件…* 下列出的 PGN 文件中的对局（等级分榜提供下载的对局、其他程序的对局），从其头信息中读取；这些对局中的引擎以 PGN 中的名称识别，如果某个名称在忽略大小写和空格后与库中某个引擎的名称相同（例如“stockfish  17”对应“Stockfish 17”），它就是该引擎：其对局计为该引擎的对局，该引擎的参考 Elo 可以作为这些对局的锚点。不会自动应用更宽松的匹配：“Stockfish 17 64-bit”会一直作为单独的引擎，直到你在 *PGN 棋手…*（位于库中引擎数量旁边，或在 *PGN 文件…* 中）中指定它是哪个引擎。该窗口按名称列出不对应库中引擎的棋手，并提供搜索：对每个棋手，可以选择*单独的引擎*（默认）或库中的一个引擎。在忽略大小写后由两个库中引擎共有的名称会以警告色显示，由你来选择；可能对应的引擎（其名称是该棋手名称的开头）会作为建议显示（*也许是 …？*），但从不自动应用。添加 PGN 文件后，如果有需要决定的内容，该窗口会自动打开。这些选择（包括选择单独的引擎）与引擎一起保存（引擎重命名后仍然有效），适用于所有 PGN 文件以及为参考 Elo 导入的等级分榜；关闭窗口时会按这些选择重新读取对局。等级分榜会说明 PGN 文件中包含多少个库中引擎，其工具提示会说明是哪些；
- *锚点*：平均值为 0，或者把某个引擎固定在某个等级分上（默认为第一个有参考 Elo 的引擎）。

### 等级分榜
<!-- en: rating-list c726b55e -->

列表，可设定最少对局数。除了 Elo、± 和对局数之外，每个引擎还显示其得分、胜（+）、和（=）、负（−）、和棋率、*对手*：它逐局遇到的对手的平均等级分、*LOS*：根据两个等级分及其误差的协方差计算的、它强于列表中下一个引擎的概率（超过 1000 个引擎时为近似值，其工具提示会说明），以及*差距*：它比下一个引擎高出的 Elo。点击列标题会按该列排序（# 保持按等级分的名次）；右键点击可以显示或隐藏列（*差距*一开始是隐藏的）。点击一个引擎会打开它的信息卡。

*复制*为文本或 BBCode，勾选*带页眉*会把下面所说的页眉放在列表上方。*导出…*：包含所有列的 CSV；HTML 页面（浅色或深色）和 Markdown（GitHub 和论坛会显示为表格），两者都以一个说明列表如何生成的页眉开头：计入的锦标赛和 PGN 文件、对局数及白方胜、黑方胜的局数、和棋数和白方得分、锚点、筛选条件、最少对局数、日期和版本；还有*用于 Ordo 的对局…*：以只含头信息的 PGN 输出计入的对局，可供 Ordo 和 BayesElo 读取（`ordo -p ratings.pgn -o ratings.txt`）。

### 引擎信息卡
<!-- en: engine-card 80442e81 -->

引擎的信息卡：它的等级分、总体成绩和按时限划分的成绩、超时判负、崩溃和非法着法（每局对局都可以在其锦标赛中打开）、它参加的锦标赛（每个都可以打开）、从着法注释中读取的平均深度、每步时间和 NPS，以及它在每个锦标赛之后的等级分。在*引擎*页面中，*它的成绩…* 可以转到这里。

### 交手记录
<!-- en: head-to-head 1021ba2f -->

两个引擎之间的对战：比分、Elo 和 LOS、两局都下完的对局对的五项分布计数，按时限和按锦标赛划分，它们的对局（每局都可以在其锦标赛中打开），以及*导出对局…*。

### 进度
<!-- en: progress e2ea28fc -->

勾选的引擎在其参加的每个锦标赛之后的等级分，绘制在时间轴上：一个引擎的各个版本并排显示。

## 直播
<!-- en: broadcast c2f489e7 -->

正在进行的锦标赛的*直播*标签页在比赛进行时发布它；快照每秒刷新两次。*显示的对局*选择发送到 TLCS 和网页的对局：自动选择，或者在*实时*标签页中选择的那一局。

### 实时文件
<!-- en: live-files 09341896 -->

以原子方式写入你选择的文件夹，可发布到任意位置（FTP、rsync、网站）：`live.pgn`（进行中的对局）、`standings.html`（排名和交叉表）、`tournament.json`（全部内容，供脚本使用）。

### TLCS 服务器
<!-- en: tlcs-server 712f28cb -->

UDP 端口，默认 16001：Tom's Live Chess Server 的协议，使 TLCV 和其他 TLCS 查看器可以跟踪锦标赛（棋盘、棋钟、PV、交叉表和已下的对局）。它经过了 node-tlcv 的验证。*每局一个端口*让每局同时进行的对局使用各自的端口：*实时*标签页中的第 1 局使用该 UDP 端口，第 2 局使用下一个端口，依此类推。每个端口在其对局开始时打开，有各自的客户端数和登录数限制，并在每局结束后收到交叉表；此时*显示的对局*不再适用。

### 网页
<!-- en: web-page 1d4c78b3 -->

TCP 端口：由 fastchess-gui 自己提供的网页，网络上的任何浏览器都可以访问，只读，每秒刷新。所关注的对局（第一局进行中的对局，或者被点击的那一局）位于中间：棋盘上显示上一步、被将军的王、坐标和箭头；每位棋手的棋钟以大字显示；每个引擎的评估以大字显示，并标明谁在思考，其搜索以小方块显示（深度/选择性深度、节点数、速度、时间、残局库命中数、哈希），以及它的主要变化；还有着法，开局库着法以斜体显示。用棋盘下方的箭头或 ← → 键浏览着法（在最后一步之后按 ▶ 会回到正在进行的对局），用 ⇅ 或 F 翻转棋盘，还可以复制对局的 PGN 或局面的 FEN。

对局旁边的标签页显示排名和交叉表、所关注对局的图表、每个引擎每步的平均搜索数据及其异常、赛程中接下来的对局（瑞士制或淘汰赛会随着比赛的进行为后续轮次配对）、已下对局的统计和异常，以及赛事信息。每局进行中的对局都显示在下方，每位棋手旁边有一个小评估条。*Moves* 在字母（Nf3）和棋子符号（♘f3）之间切换着法的写法，主题跟随系统或设为浅色或深色；浏览器会记住这些选择。该页面不从其他地方加载任何内容，在手机上也能使用。*Download the games (PGN)* 提供锦标赛的 PGN 文件，直到最后记录的一局。页面所读取的 `state.json` 包含所有这些内容，供脚本使用。引擎的标志（见[外观](#外观)）显示在其名称旁边，以程序根据标志生成并自己提供的小 PNG 图片的形式；页面只能获取锦标赛中引擎的标志。

### lichess
<!-- en: lichess 7597e86f -->

lichess 直播，使用 lichess 的棋盘、评估条和聊天，互联网上的任何人都可以观看。它需要一个具有 `study:write` 权限的个人 API 令牌（*在 lichess 上创建令牌…*），只保存在配置文件夹的 `settings.json` 中，离开输入框时保存。如果没有指定轮次，会创建一个以锦标赛命名的直播，除非勾选*列入 lichess 的直播列表*，否则不公开列出；开播后会显示它的链接。否则，对局会发送到给定 URL 或 id 的轮次（一个通过推送而不是源 URL 提供数据的直播）。进行中的对局每 8 秒连同棋钟推送一次，每局结束的对局推送一次；一个轮次容纳 64 局，之后会在同一个直播中创建下一个轮次。只推送开启之后结束的对局；锦标赛文件夹中的 `lichess.json` 记住对局推送到了哪里，因此恢复的锦标赛会继续同一个直播。lichess 只保留发送给它的内容中的棋钟（它会丢弃 `[%eval]` 和着法注释的文字）：它的评估条是它自己计算的，引擎的评估不会在那里显示。

连接使用程序内置的 Mbed TLS，只信任为 lichess.org 签名的根证书（Google Trust Services）和 Let's Encrypt 的根证书。连接会经过 `HTTPS_PROXY`（或 `ALL_PROXY`）指定的 HTTP 代理，例如 `http://proxy.example:3128` 或 `http://user:password@proxy.example:3128`，`NO_PROXY` 中的主机除外；在 Windows 上，代理同样取自这些变量，而不是系统设置。不支持 SOCKS 代理。

### 直播团体赛
<!-- en: a-team-match-on-the-air fd32027f -->

团体赛会在各处显示两队的比分：网页的页眉和排名上方（附有 A 队的得分率、Elo ± 和 LOS）、`standings.html`（两队，然后是每队的引擎对另一队引擎的成绩）、`tournament.json` 和 `state.json`（`teams`、`team_elo`、`team_elo_error`、`team_los`），以及 TLCS 交叉表中表格下方的一行（“Lynx 17½ - 18½ Otter · 48.6 % · Elo -9.7 ± 31.2”）。它的对局在 PGN 文件中带有 `WhiteTeam` 和 `BlackTeam` 标签，导出时会保留。

### 把网页放到互联网上
<!-- en: putting-the-web-page-on-the-internet b19f02f8 -->

无需在路由器上开放端口，就可以从任何地方观看网页：在*直播*标签页的*网页*下勾选*发布到互联网*。锦标赛进行时，fastchess-gui 会打开一条到隧道服务的 SSH 隧道（libssh2，内置于程序中），隧道服务为页面提供一个公共 https 地址；不需要安装任何东西。

- *localhost.run*（默认）：免费，无需账户。它的地址不时会变化，速度也有限制；页面及其状态以压缩形式发送，因此影响不大。fastchess-gui 知道它的主机密钥：连接到其他任何主机都会被拒绝。
- *其他 SSH 服务器*：它的主机、端口和用户，以及它为页面开放的端口（与 `ssh -R REMOTE_PORT:localhost:PORT user@host` 所要求的相同；0 表示由服务器选择）。只能使用无需密钥或密码即可让用户登录的服务器（认证方式“none”），并且服务器必须支持 curve25519-sha256、2048 到 4096 位的 RSA 主机密钥，以及 AES（GCM 或 CTR）。服务器的密钥在第一次连接时被信任，并保存在配置文件夹中（`known_hosts.json`）；如果密钥发生变化，隧道会停止并说明这一点，*信任新密钥*用于服务器所有者确认密钥确实已更改的情况。

标签页显示状态（正在连接、直播中及连接数、正在重新连接，或错误），得知公共地址后还会显示该地址，附有*复制*、*打开*（以观众的视角查看页面）和供手机扫描的二维码（点击可放大）。隧道失败后会自行重新连接，每次等待的时间稍长一些，如果地址发生变化，会显示新地址。隧道随网页或锦标赛一起停止。

其他隧道也可以使用，需要单独启动：例如使用 Cloudflare 的隧道，先开启网页（此处端口为 8080），然后运行 `cloudflared tunnel --url http://localhost:8080`；它会输出一个地址，例如 `https://some-words.trycloudflare.com`。ngrok、tailscale funnel 或 nginx 这样的反向代理（也可以放在单独的路径下：`location /live/ { proxy_pass http://localhost:8080/; }`）的用法相同。

该页面是只读的：它只响应对页面、页面状态和 PGN 文件的 GET 请求，从不提供请求中指定的文件，页面中的任何操作都不会改变锦标赛。每个请求单独响应，最多同时 32 个，请求必须在一秒内到达，并在十秒内得到响应，因此缓慢或不发送数据的访问者不会妨碍其他人；在隧道后面，每位观众的连接都算作其中之一：同时转发 40 个，另有同样数量的连接排队等待，再多的会被拒绝；发送的数据多于页面所需的观众会被单独断开。PGN 文件同时最多有两个下载，下一个会被要求稍后再来。状态从不被缓存，隧道也不会缓存，因此观众看到的是实时进行的对局；页面本身由浏览器保存，并在每次加载时重新检查。*直播*标签页中显示的观众数根据页面发出的请求统计，因此在隧道后面计数也是准确的。

观众可以看到锦标赛的名称、引擎的名称、它们的等级分、搜索和异常、开局以及已下对局的 PGN 文件。文件夹和引擎的文件不会公开。无界面模式：

```
fastchess-gui --run FOLDER --tunnel                      # localhost.run, the address printed on the console
fastchess-gui --run FOLDER --web 8080 --tunnel ssh://user@host[:port][/remote_port]
```

### 观众在哪里交流
<!-- en: where-the-viewers-talk eb3ef90c -->

该页面没有自己的聊天功能；它指向交流发生的地方。*网页*下的*聊天链接*（Discord 邀请、Twitch 频道、论坛帖子；仅限 https，其他链接会被拒绝，并在输入框下方显示一条消息）会在页面的页眉中放一个 *Chat* 按钮，在新标签页中打开该链接。对局推送到 lichess 时，页面还会链接到 lichess 的轮次，那里有自己的聊天。

*Discord 服务器 ID* 会在 *Event* 旁边添加一个 *Discord* 标签页，以页面的浅色或深色主题显示 Discord 自己的服务器小组件：服务器名称、在线成员、语音频道和*加入*按钮，不显示消息。服务器所有者在“服务器设置”的“小组件”中开启它（“启用服务器小组件”），那里也会显示可复制的服务器 ID（17 到 20 位数字）；开启开发者模式后，右键点击服务器图标也可以使用*复制服务器 ID*。只有当观众打开该标签页时才会从 discord.com 加载小组件，此时 Discord 会看到该观众的访问（其地址、浏览器，以及 Discord 登录信息，如果有的话）；没有 ID 时，页面除了 fastchess-gui 之外不联系任何人。聊天链接和 lichess 链接在观众点击之前不发送任何内容，点击时也不发送来源页（referrer）。以无界面模式运行的设置文件（`--run SETUP.json`）从 `web_chat_link` 和 `web_discord_id` 中读取这两项。

## 无界面模式
<!-- en: headless-mode 3471fbb3 -->

```
fastchess-gui --run TOURNAMENT_FOLDER     # resume a tournament
fastchess-gui --run SETUP.json            # create one from a setup or template file, with the profile's engines
```

不打开窗口；版本号以及之后的进度会输出到控制台，与在窗口中一样，包括无法启动的引擎的尝试、引擎被搁置（附其引擎日志）或恢复，以及每 20 局和结束时的排名（团体赛：两队的比分，然后是每队的引擎对另一队引擎的成绩），锦标赛的排名以复制排名时附带的那一行结尾（对局数、和棋、时限、开局库和赛事）。**Ctrl+C** 会在进行中的对局下完后停止，之后可以从命令行或图形界面恢复锦标赛。退出码：0 完成，1 进行中出错，2 没有可运行的内容，3 在结束前停止（因 Ctrl+C，或者除无法启动的引擎外已没有可下的对局）。配置文件夹中**设置**的内存预算和 GPU 同样适用于它。

`--detach` 则在后台进行：命令立即返回，锦标赛在没有终端的情况下继续；窗口以同一个配置文件夹打开时会显示它（连接到它），`--attach` 可以与它通信：

```
fastchess-gui --run FOLDER --detach         # in the background, on a local socket
fastchess-gui --attach FOLDER               # its control channel on the standard input and output
```

窗口也以同样的方式驱动每个锦标赛：`--run FOLDER --control socket`（或 `--control stdio`）进行锦标赛但不输出，而是与窗口以 JSON 行通信：锦标赛的事件（状态、每条日志记录、逐步更新的进行中对局、记录的每局对局、日志、结束）和窗口的命令（暂停、继续、停止、修改、结束一局对局、用 `--allowance THREADS:MEMORY_MB:GPUS:ONE` 设定它在本机中的份额）。每个方向的第一行都是一个问候，`{"hello": {"protocol": 1, ...}}`；通过 `--attach` 的脚本会收到锦标赛的问候和事件，并可以发送 `{"c": "pause"}` 这样的命令。同一时间只有一个窗口（或脚本）与一个锦标赛通信；当 `--attach` 的标准输入结束或其输出不再被读取时，它会释放该锦标赛，因此脚本在读取回应期间应保持其输入打开。

锦标赛可以同时进行直播，与在*直播*标签页中一样：

```
fastchess-gui --run FOLDER --tlcs 16001             # a TLCS server on UDP port 16001
fastchess-gui --run FOLDER --tlcs 16001 --tlcs-lanes  # one port per game: 16001, 16002…
fastchess-gui --run FOLDER --web 8080               # the web page on http://<this machine>:8080/
fastchess-gui --run FOLDER --tunnel                # the web page on the internet (serves it too, --web's port or 8080)
fastchess-gui --run FOLDER --live-files [DIR]       # live.pgn, standings.html, tournament.json ("live" by default)
fastchess-gui --run FOLDER --lichess new            # a new lichess broadcast; or --lichess ROUND_URL|ROUND_ID
```

`--lichess` 从环境变量 `FCG_LICHESS_TOKEN` 中读取令牌，或者使用配置文件夹中的令牌。

这些选项可以组合使用。开启直播时保存的设置文件，不带这些选项也会以同样的方式直播。对于局域网以外的观众，请在路由器中开放端口：TLCV 和 node-tlcv 连接到 TLCS 端口。对于网页，使用隧道可以避免开放端口（见[把网页放到互联网上](#把网页放到互联网上)）。

## 机器
<!-- en: machines 4d8fbfef -->

用来运行锦标赛的其他计算机：测试机、服务器、第二台电脑。**设置** > *机器*列出它们。程序通过 SSH 访问机器：除了 SSH 服务器之外，机器上不需要开放任何东西，程序也不保存任何机密。

### 添加机器
<!-- en: adding-a-machine f1f15823 -->

点击*添加机器*，然后在它的卡片上填写：

- *名称*、*主机*（它在网络上的名称，或其地址）、*端口*（22）和*用户*，即锦标赛在机器上运行所用的账户；
- *登录方式*：*SSH 代理*（Linux 和 macOS 上为 ssh-agent，Windows 上为 Pageant 或 *OpenSSH Authentication Agent* 服务；用 `ssh-add` 把你的密钥加入其中），或者*密钥文件*，RSA 或 Ed25519（`~/.ssh/id_ed25519`）。密钥文件的口令每次会话询问一次：它保留在内存中，从不写入任何地方。机器必须认识该密钥：密钥的公钥部分（`id_ed25519.pub`）放在机器上的 `~/.ssh/authorized_keys` 中（`ssh-copy-id user@host` 会把它放到那里），对于 Windows 机器的管理员，则放在 `C:\ProgramData\ssh\administrators_authorized_keys` 中；
- *那边的文件夹*：机器上 fastchess-gui 的文件夹，用于存放程序、锦标赛、开局库和残局库，相对于用户的主文件夹（默认为 `fastchess-gui`）或绝对路径（`/srv/fcg`、`D:\fcg`）；
- *预算*：机器上的锦标赛同时可以使用的核心和内存；0 表示使用测试所测得的值，即除一个线程外的所有线程和 80% 的内存。

*测试连接*会登录，然后报告机器的系统、线程数、内存、其文件夹所在位置的剩余空间，以及是否安装了 fastchess-gui、是哪个版本。第一次连接时会显示机器的主机密钥（其 SHA256 指纹），并从此信任它（保存在配置文件夹的 `known_hosts.json` 中，直播隧道的主机密钥也保存在这里）。如果之后密钥发生变化，程序不会发送任何内容，卡片会说明这一点，并为重新安装过的机器提供*信任新密钥*。每次失败都会指明是哪台机器以及该怎么做：无法访问的主机、机器拒绝的密钥（以及其公钥部分应放在哪里）、不正确的口令、没有运行的代理。

*安装 fastchess-gui*（已安装时为*更新 fastchess-gui*）通过 SFTP 把程序复制到机器的文件夹中，然后检查它能否在那里启动（`fastchess-gui --version`）。当机器运行相同的系统时（Linux x86-64 到 Linux x86-64），它复制本程序；对于其他系统，例如从 Linux 管理 Windows 机器，请下载该系统的发布版本，并在卡片上选择其程序（*适用于 Windows x86_64 的 fastchess-gui*）。因网络中断的复制会从停止处继续。

### 机器上的引擎
<!-- en: engines-on-a-machine 4b00e462 -->

*此机器上的引擎*：机器上有的库中引擎，每个都附有它在那里的路径（`/opt/engines/stockfish`、`C:\Engines\sf.exe`）。*检查引擎*检查每个路径：程序存在、可以运行，并在 10 秒内响应 `uci`（WinBoard 引擎为 `xboard`）。旁边的标记及其工具提示说明检查的结果：引擎的名称，或者它无法运行的原因（缺失、不可执行、为其他系统构建、没有响应）。

机器上缺少的引擎可以用其所在行的*复制…* 复制过去（也可以用命令面板中的*将 <引擎> 复制到 <机器>*，或因引擎在那里没有路径而被拒绝开始时提供的按钮）。打开的面板首先说明要发送的内容：程序、它的大小，以及从其开头字节读出的目标系统（Windows 程序，Linux 或 macOS 程序及其是否为通用二进制，或者脚本）。机器无法运行的程序在发送任何内容之前就会被拒绝，并说明应选择哪个构建版本：“Alpha 是 Windows 程序；tc-box 运行的是 Linux：请选择 Linux 构建版本（Alpha）”。架构也会被考虑（x86-64 或 arm64）；x86-64 构建版本在 arm64 Mac 上只能在 Rosetta 下运行，程序不认识的格式照样会被复制：这两种情况只会说明，不会拒绝。脚本只会发送到 Linux 或 macOS 机器，并且只有当其第一行的解释器（`python3`、`/bin/sh`）在那里存在时才会发送。*选择 <系统> 构建版本（<引擎>）…* 选择本机上的另一个文件，例如该引擎的 Windows 构建版本，以同样的方式检查，并为那台机器保留它：之后的比较和替换都使用它，而不是引擎库中的程序。

*连同其文件夹*把引擎的整个文件夹（它的工作目录，或程序所在的文件夹）复制到程序旁边，适用于需要旁边文件的引擎：它的网络、开局库。面板首先统计其中的文件数和总大小，并指出指向该文件夹内部的引擎选项（网络的 `EvalFile`）：在机器上进行的锦标赛中，这些选项指向那里的副本，该文件夹就是引擎的工作目录。超过 2000 个文件的文件夹不提供此选项（`/usr/bin` 中的程序不应连同其文件夹一起复制），`.git` 文件夹会被排除；对于 Windows 机器，Windows 不允许的文件名（`:`、`*`、`?`、末尾的点、`CON`、`NUL` 等）会被指出，并在复制开始之前就停止复制。文件按原样复制，包括行尾符。

*复制*通过 SFTP 把文件发送到机器文件夹中的 `engines/<engine>/`，在后台进行，显示剩余时间并提供*取消*，中断后从停止处继续；复制后会将每个文件的 SHA-256 与本机的进行比较，那里已有且相同的文件不会重新发送。在 Windows 上，程序保留或加上 `.exe` 扩展名；在其他系统上，程序会被设为可执行（`chmod 755`）。然后，引擎在机器上的路径会被设为该副本，并像*检查引擎*一样进行检查。在 Mac 上，从其他计算机复制过来却无法启动的程序可能需要签名或解除隔离：消息会给出需要在那里运行的两条命令（`codesign -s -` 和 `xattr -d com.apple.quarantine`）；程序本身不会运行它们。

*构建版本*列按 SHA-256 比较那里的引擎与本机的引擎（*检查引擎*和*比较*会进行比较，本机程序的哈希只计算一次，直到程序发生变化）：*与本机构建版本相同*，或*那里是不同的构建版本*，附有*用本机的替换*。替换会把本机的程序复制到机器文件夹中该引擎的文件夹，并让引擎指向那里：机器上其他位置的程序（`/opt/engines/stockfish`）永远不会被覆盖，它保持原样。

### 机器上的开局库和残局库
<!-- en: books-and-tablebases-on-a-machine 8542f2e7 -->

*检查设置所用的文件*按大小和 SHA-256 将设置的开局库和参赛者自己的开局库与机器的开局库文件夹进行比较（同名但内容不同的开局库不算同一个开局库），并按名称和大小将设置所用的最多 6 子的 Syzygy 文件与机器的残局库文件夹进行比较。*推送缺失的文件*在后台复制缺失或不同的文件，并显示剩余时间；每个开局库复制后按哈希检查，每个残局库文件按大小检查，被中断的复制会继续。7 子残局库不提供推送：它们需要数 TB 的空间。机器上缺少开局库时，锦标赛不会开始；缺少残局库只是警告（裁定和引擎在没有它们的情况下照常工作）。

### 在机器上运行锦标赛
<!-- en: a-tournament-on-a-machine 8f918d9a -->

在设置中，*运行于*（在*并发*中）选择锦标赛在哪里进行：*本机*，或某台机器。然后*开始*会在那里做好准备：机器上必须安装与本机相同版本的 fastchess-gui（否则提供*更新 fastchess-gui*），每个引擎都必须在机器上有路径（否则开始时会提供*将 <引擎> 复制到 <机器>…*），设置所用的开局库必须在机器的开局库文件夹中（否则开始时会说明缺少哪个，*推送缺失的文件*会把它放到那里）；缺少残局库只是警告。锦标赛在机器文件夹的 `tournaments/` 中获得自己的文件夹，引擎、开局库和残局库使用它们在那里的路径，锦标赛的进程在那里脱离 SSH 会话启动（`fastchess-gui --run <folder> --detach`）：无论窗口或网络发生什么，它都会继续进行。窗口像跟踪本机的锦标赛一样跟踪它：实时、对局、排名、暂停、停止和修改，都通过其进程的控制通道进行（通过 SSH 运行 `fastchess-gui --attach <folder>`）。

它在主页上的卡片显示*在 <机器> 上*，连接中断时显示*正在连接 <机器>…*：窗口会自行重新连接，每次失败后等待的时间稍长一些，并从其副本停止的地方继续接收事件。日志和 PGN 文件在增长时每隔几秒复制回本机上该锦标赛的文件夹，以便等级分、导出和提交检查清单读取它们；机器上的文件夹仍然是基准（本机的 `machine.json` 说明是哪台机器和哪个文件夹）。关闭窗口后，锦标赛会在那里继续进行；下次启动时会重新显示。对机器上被中断的锦标赛点击*继续*，会在那里恢复它。机器的预算（其核心和内存）由它自己的锦标赛共享，与本机的预算分开。一个锦标赛在一台机器上进行：它的对局不会分散到多台机器上。

机器需要 OpenSSH 服务器（Linux、macOS、BSD；Windows 10 1809 及更高版本），带有 RSA 主机密钥和 SFTP，两者默认都有。无论用户的 shell 是什么（fish 或 csh 都可以），命令都通过 `sh` 执行；在 Windows 上则通过 cmd 执行，即其 OpenSSH 服务器的默认 shell。

### 从本机对弈机器上的引擎
<!-- en: engines-played-from-this-computer 8c14dc16 -->

引擎库中的引擎可以在某台机器上运行，而锦标赛在本机进行：例如 GPU 机器上的 GPU 引擎、为其他系统构建的引擎、专门留给某个引擎的机器。在它的信息卡上，*运行于*选择*本机*或某台机器；此时*那边的程序*和*那边的工作目录*是机器上的路径（留空：程序在那里所在的文件夹），各个 *…* 按钮（包括指定文件的选项的按钮）浏览的是机器上的文件。有了机器之后，*添加…* 中会提供 *\<机器\> 上的程序…*，*导入…* 中会提供 *\<机器\> 上某个文件夹中的所有引擎…*，机器的*添加引擎…* 中会提供*那边的程序…*。引擎的读取、检查，以及在控制台、快速测试和锦标赛中的对弈，都与本机的引擎相同。它的路径也就是机器引擎列表中的路径，它在那里的程序的 SHA-256 会指出它何时被重新构建（标记为 Δ，并重新读取）。

机器必须已经测试过一次（*测试连接*），这样它的主机密钥才是已知的：引擎永远不会连接到密钥未经显示和信任的机器。密钥如有口令，每次会话询问一次，在第一次读取或开始之前询问，并保留在内存中：锦标赛的进程从窗口获得口令并保留它，使锦标赛在窗口关闭后继续进行。在终端中使用 `--run` 时不会询问口令：请在那里使用 SSH 代理。

每个引擎都通过一个中继 `fastchess-gui --remote-engine <key>` 启动，该中继由用这个引擎下棋的进程提供：到机器的一条 SSH 连接最多用于十个引擎（OpenSSH 服务器的 `MaxSessions`），每个引擎都从它在那里的文件夹启动。中继消失后，如果引擎没有自行结束，也会在那里按其进程 ID 被结束（在 Linux 或 macOS 机器上；在 Windows 机器上则关闭它的通道）。

*检查*会测量到机器的往返时间，即几次 `isready` 的中位数。棋钟会计入这段时间：当它超过加秒的 5%（没有加秒时，超过每步可用时间的 5%）时，设置的摘要会发出警告，并提供*将余量设为 … ms*（往返时间的两倍）。从未测试过的机器会阻止开始；锦标赛在引擎所在机器以外的另一台机器上进行时，也会阻止开始（在引擎所在机器上进行的锦标赛会在那里把它当作自己的引擎来下）。

锦标赛进行时，主页在核心下方有一行*机器*：每台机器，显示已连接以及在那里下棋的引擎，或者自何时起没有响应。没有响应的机器在*需要处理*下显示为一个条目：它的引擎的对局会被搁置并重新尝试，其他对局继续进行，附有*重试*和*测试 \<机器\>*。引擎因连接中断而输掉的对局（结束方式为断开连接）会被作废并重下，并连同原因写入日志（`connection to its machine lost: <machine>`）；*稳定性*会单独统计它，而不算作引擎崩溃。一小时内断开超过三次的机器，其引擎会被搁置。本机的核心、内存和 GPU 不计算机器上的引擎，只计算它们的中继；机器的预算（由它自己的锦标赛共享）目前也还不计算它们。

### Windows 机器
<!-- en: a-windows-machine 58ae029a -->

Windows 10（1809 及更高版本）和 Windows 11 自带 OpenSSH 服务器，但默认不安装。以管理员身份在 PowerShell 中运行：

```powershell
Add-WindowsCapability -Online -Name OpenSSH.Server~~~~0.0.1.0
Start-Service sshd
Set-Service sshd -StartupType Automatic
```

安装会在防火墙中开放端口 22。然后把你的公钥放到 `C:\Users\<user>\.ssh\authorized_keys` 中；对于 Administrators 组的账户，则放到 `C:\ProgramData\ssh\administrators_authorized_keys` 中，该文件只允许 Administrators 和 SYSTEM 读取（这两个组以其 SID 指定，在任何语言的 Windows 中都相同）：

```powershell
icacls C:\ProgramData\ssh\administrators_authorized_keys /inheritance:r /grant "*S-1-5-32-544:F" /grant "*S-1-5-18:F"
```

请保留 cmd 作为服务器的 shell：fastchess-gui 使用 cmd，而不是 PowerShell（如果在 `HKEY_LOCAL_MACHINE\SOFTWARE\OpenSSH` 下设置了 `DefaultShell` 值，请删除它）。在机器的卡片上选择 Windows 发布版本中的 `fastchess-gui.exe`，然后点击*安装 fastchess-gui*。

## 文件
<!-- en: files 837f3661 -->

所有内容都保存在配置文件夹中：Linux 上为 `~/.local/share/fastchess/fastchess-gui/`，Windows 上为 `%APPDATA%\fastchess\fastchess-gui\`，macOS 上为 `~/Library/Application Support/fastchess/fastchess-gui/`。程序创建的文件其他用户不能写入，`settings.json` 在保存了 lichess 令牌之后只有其所有者可以读取。**设置**中显示配置文件夹，并附有*打开文件夹*。

### 便携模式
<!-- en: portable-mode 29ddbe3b -->

如果程序旁边（`fastchess-gui.exe` 或 `fastchess-gui` 旁边，macOS 上为 `fastchess-gui.app` 旁边）有一个名为 `portable` 的文件（空文件，没有扩展名），配置文件夹就改为程序旁边的 `data` 文件夹，默认的锦标赛文件夹为 `data/runs`：除了为锦标赛、导出等选择的文件夹之外，不会向其他任何地方写入内容。位于程序文件夹中的内容（引擎、开局库、残局库、测试集、等级分和设置所用的 PGN 文件、选择的文件夹）的路径，在配置文件夹的文件中以相对于程序文件夹的形式保存，因此整个文件夹可以移动、复制到另一台机器，或者从 U 盘运行，无论盘符是什么，引擎都能再次找到。**设置**会在配置文件夹旁边显示*便携模式*。要沿用现有的配置文件夹，请把其中的文件复制到 `data` 中。`--profile` 仍然可以选择另一个文件夹，此时不处于便携模式。锦标赛保留创建时的引擎路径：请在移动文件夹之前恢复未完成的锦标赛。在 macOS 上，请先解除隔离（见 README）：否则 macOS 会从一个临时位置运行该应用程序，而 `portable` 文件不在那里。

### 配置文件夹
<!-- en: the-profile-folder 91838f38 -->

- `engines.json`：引擎库，`engines.json.bak` 是它的上一个版本，在前者丢失时读取；
- `setup.json`：上一次的设置；`profiles.json`：你为设置的各个部分保存的配置；`templates/*.json`：保存的模板；`queue.json`：队列；
- `book-cache/`：为参赛者自己的开局库从 PGN 开局库转换而来的 Polyglot 开局库（30 天未使用后删除）；
- `layout.ini`：窗口布局和工作区的面板；`layouts.json`：按名称保存的布局；`fastchess-gui.log`：上一次会话的日志；
- `suite.json`：测试集页面的上一次设置；`suites/<suite>-<date>.json`：完成的测试集运行结果；
- `board.json`：棋盘页面的分析和对局的设置；`analyses/*.json`：逐步分析过的对局，每局一个文件；`games/*.pgn`：从棋盘页面下的对局；
- `settings.json`：锦标赛文件夹（在**设置**中选择了其他文件夹时）、*软件渲染*、*某个文件夹中的所有引擎…* 的文件夹、*导出给等级分列表…* 的测试者和地点、lichess 令牌、窗口的大小和位置、指南面板的宽度、“开始使用”卡片是否已隐藏、新版本检查（是否需要、上次检查的时间、找到的发布版本、提示是否已隐藏）、外观（棋盘颜色、棋子、走棋声音），以及本机的预算（锦标赛使用的核心、内存和 GPU，*有空闲核心时启动*）；
- `logos/`：引擎的标志，即在其信息卡上选择的图片的副本；
- `machines.json`：**设置**中的远程机器（地址、文件夹、预算、引擎路径以及上次测试的结果；不含口令），`known_hosts.json` 是受信任的主机密钥，包括机器的和隧道的；
- `running.json`：当前正在进行的锦标赛及其权重，每个锦标赛停止时从中移除；启动时如果找到它，会据此确定要重新显示哪些锦标赛（在没有窗口时继续进行的锦标赛）或恢复哪些锦标赛；
- `runs/`：锦标赛，除非选择了其他文件夹（见[锦标赛的文件夹](#锦标赛的文件夹)）。

### 锦标赛的文件夹
<!-- en: a-tournaments-folder 76959723 -->

比赛为 `runs/<date>_<A>_vs_<B>/`，锦标赛为 `runs/<date>_<name>/`（在 `runs/` 或所选的文件夹中），每个一个文件夹，可以移动、复制、压缩和发送：

- `tournament.json`：格式、参赛者（复制的引擎及其选项）和条件；
- `setup.json`：它启动时所用的*新建锦标赛*页面设置，供*克隆*和*重新开始，使用…*读取（见[队列与重新开始](#队列与重新开始)）；由旧版本启动的锦标赛没有这个文件；
- `journal.jsonl`：此后发生的一切，每个事件一行（开始的对局对、结束的对局、修改、瑞士制和淘汰赛的配对）；它与 PGN 文件一起是恢复时读取的内容。一局对局先写入磁盘，再写入它的那一行，因此断电最多丢失正在进行的对局。没有任何一行指向的对局文本（保存时被修改取消的对局，或崩溃留下的对局）会被替换为空行，因此其他 PGN 查看器只会显示锦标赛的对局；
- `tournament.lock`：由进行该锦标赛的程序持有；打开该文件夹的其他程序只能显示它；
- `<name>.pgn`：cutechess / fastchess 风格的着法注释，`{+0.35/18 1.234s}`，评分以走棋一方的视角给出；对局按结束顺序排列（日志按每局对局在文件中的位置找到它；*对局*标签页中的*全部导出…* 以及*同时把每局对局追加到*的文件按赛程顺序排列）；
- `<name>-chessbase.pgn`：`{[%eval 0.35,18] [%clk 0:00:59.200] [%emt 0:00:01.234]}`，评估以白方的视角给出，供 ChessBase / Fritz 和 Lichess 读取；
- `<name>` 是锦标赛创建时的名称（之后重命名也会保留这些文件），其中 Windows 不允许的字符会被替换为 `_`，并截断到 64 字节；`tournament.json` 记录这两个名称。没有名称的锦标赛、较早的锦标赛，或从 0.2.x 导入的比赛，使用 `games.pgn` 和 `games-chessbase.pgn`；
- `lichess.json`：其对局推送到的 lichess 直播和轮次（不含令牌）；
- `processor.tsv`：每局对局的引擎占用的处理器时间，用于恢复后的锦标赛的*处理器占用*；
- `fastchess-gui.log`：进行该锦标赛的进程的日志（每个锦标赛在各自独立的进程中进行）；`control.json`，在有进程进行该锦标赛时存在：说明其本地套接字的位置（文件夹中的 `control.sock`，路径太长时在用户的运行时文件夹中；Windows 上为命名管道），以及哪个进程在监听；
- `logs/game-N.log`：第 N 局对局（*对局*标签页中显示的编号）期间与两个引擎交换的每一行，附有发送或读取的时间（`W>` 为发送给白方引擎的内容，`W<` 为从其输出读取的内容，`W!` 为从其错误输出读取的内容：断言、崩溃消息），用于超时判负、崩溃、卡住或因非法着法而输掉的对局（如果要求，也可以是每局对局）。保留每个引擎的前 300 行和对局的最后 5000 行，按到达顺序排列。这正是引擎作者重现错误所需要的。对于 WinBoard 引擎，它显示的是 UCI 一侧；`FCG_WB2UCI_LOG` 给出 WinBoard 一侧；
- `logs/start-<engine>.log`：无法启动的引擎最后一次失败的启动尝试：它的程序、错误，以及在此之前与该局对局的引擎交换的行（见[无法启动的引擎](#无法启动的引擎)）。

从别人那里收到的文件夹可以放心打开：*同时把每局对局追加到*的文件必须是 `.pgn` 文件（其他名称会被忽略，并给出警告），日志、PGN 文件或锁文件是符号链接的文件夹不会以写入方式打开，因此它无法让程序向其外部写入。恢复它会运行其 `tournament.json` 中指定的引擎，与任何锦标赛一样。

用 0.2 版下的比赛会出现在主页上：*导入它们*会把它们转换为已结束的锦标赛。

## 命令行
<!-- en: command-line bba4b98e -->

```
fastchess-gui [--profile DIR] [--autostart] [--size WxH] [--software]
              [--shot FILE.png[@WINDOW[@SECONDS]]]... [--select-game N] [--focus WINDOW]
              [--quit-after SECONDS]
fastchess-gui [--profile DIR] --run TOURNAMENT_FOLDER|SETUP.json [--tlcs UDP_PORT [--tlcs-lanes]]
              [--web TCP_PORT] [--tunnel [localhost.run|ssh://USER@HOST[:PORT][/REMOTE_PORT]]] [--live-files [DIR]] [--lichess ROUND_URL|ROUND_ID|new]
              [--control stdio|socket] [--detach] [--allowance THREADS:MEMORY_MB:GPUS:ONE]
fastchess-gui --attach TOURNAMENT_FOLDER
fastchess-gui --version
```

- `--profile DIR` 使用另一个配置文件夹；
- `--autostart` 在启动时开始已保存的设置（而不是恢复之前正在进行的锦标赛，见[暂停、停止和继续](#暂停停止和继续)）；
- `--size WxH` 以该大小在屏幕中央打开窗口，而不是按上次关闭时的样子打开，并且不改变为下次启动保存的大小和位置；
- `--software` 让处理器绘制窗口（SDL 的软件渲染器）而不是使用 OpenGL，与**设置**中的*软件渲染*作用相同，仅对本次启动有效（见[窗口的绘制](#窗口的绘制)）；
- `--shot` 在给定的秒数（默认 5）之后保存窗口的截图，WINDOW 会被切换到前台，所有截图完成后退出。它可以重复使用。WINDOW 是一个页面（`home`、`setup`、`engines`、`books`、`board`、`ratings`、`ratings-engine`、`ratings-h2h`、`ratings-progress`、`console`、`settings`）或一个标签页（`live`、`games`、`openings`、`standings`、`schedule`、`bracket`、`broadcast`）。在这种模式下会忽略鼠标，在 Linux 上窗口在屏幕外渲染（不会出现窗口；设置 `SDL_VIDEODRIVER` 可以改变这一行为）；窗口以默认大小或 `--size` 打开，不改变保存的大小和位置；
- `--focus WINDOW` 在启动时打开该页面或标签页，或者：`engines-card`（第一个引擎的信息卡）、`engines-refresh`（*刷新：文件夹中的新引擎*）、`engines-ratings=FILE`（该等级分榜的预览）、`setup-picker` 和 `setup-suggest`（引擎库的筛选框获得焦点，或选中建议的对手）、`setup-open=ROW` 和 `setup-profiles=ROW`（打开设置中的一行，或其配置列表：`format`、`time`、`openings`、`adjudication`、`engines`、`concurrency`、`pgn`）、`setup-book`（第一个参赛者自己的开局库）、`submission-export`（*导出给等级分列表…*）、`ratings-players`（*PGN 棋手…* 窗口）、`clone=DIR`（由*克隆*该锦标赛文件夹填好的*新建锦标赛*页面）、`palette[=TEXT]`（命令面板，其中已输入 TEXT）、`game-menu=N`（*对局*标签页中第 N 局对局的菜单，已选择一个结果）、`end-menu=N`（槽位 N 的对局的*以指定结果结束*，槽位从 1 开始）、`big-screen[=N]`（大屏幕，显示槽位 N 的对局）、`live-back=N`（*实时*中所关注的对局，往回退 N 个半回合）、`engines-console`（第一个引擎的控制台）、`board-analyse`（棋盘页面，正在分析）、`board=FILE`（在棋盘页面打开 PGN、FEN 或 EPD 文件；`board-analyse=FILE` 并进行分析，`board-review=FILE` 逐步分析其第一局对局）、`board-edit`（局面编辑器）、`board-play` 和 `board-play-start`（前两个引擎之间的一局对局，后者已开始）、`machines`（**设置**中第一台远程机器的卡片；`machines-test` 已测试，`machines-files` 已将设置的开局库和残局库与之比较）、`guide[=ID]`（指南面板，定位到章节 ID）、`guide-search=TEXT`（指南面板，搜索 TEXT）；
- `--select-game N` 一旦第 N 局对局（按结束顺序）存在，就在*对局*标签页中打开它；
- `--quit-after SECONDS` 停止锦标赛并退出；
- `--run`、`--detach`、`--attach`、`--control`、`--allowance`：见[无界面模式](#无界面模式)；
- `--version` 输出版本号以及窗口跟踪远程锦标赛所用通道的协议（见[机器](#机器)），然后退出。

## 故障排除
<!-- en: troubleshooting e8c4882d -->

### 程序无法启动
<!-- en: the-program-does-not-start dc0a0128 -->

- **Windows 提示程序不安全，或杀毒软件删除了它**。程序没有签名，因此 Windows SmartScreen 和一些杀毒软件不信任它。点击*更多信息*，再点击*仍要运行*，即可启动；也可以让杀毒软件放行它的文件夹。发布版本由 GitHub Actions 根据公开的源代码构建。
- **macOS 拒绝打开它**。它没有用 Apple 开发者账户签名：按住 Control 键点按（或右键点按）它，选择“打开”，然后再次点按“打开”；在 macOS 15 及更高版本上，先尝试打开一次，然后前往“系统设置”>“隐私与安全性”，点按“仍要打开”。也可以对解压后的文件夹运行 `xattr -dr com.apple.quarantine`。
- **消息说没有任何绘制窗口的方式可用，或者窗口一直是黑的**。显卡驱动缺少 OpenGL 3.2 或出错：用 `--software` 启动（由处理器绘制窗口），如果这样可以，就在**设置**中勾选*软件渲染*。在没有显卡驱动的 Wayland 下，用 `SDL_VIDEODRIVER=x11` 启动。见[窗口的绘制](#窗口的绘制)。
- **中文显示为方块**。中文需要系统字体：Windows 上为 Microsoft YaHei（微软雅黑），Linux 上为 Noto Sans CJK 或 WenQuanYi（文泉驿）（安装 `fonts-noto-cjk` 或类似的软件包）。

### 引擎无法启动
<!-- en: an-engine-does-not-start 202a67d4 -->

- **检查失败，或者锦标赛说它无法启动**。阅读引擎下方的错误信息，然后查看它的引擎日志（*引擎日志*，或锦标赛文件夹中的 `logs/start-<engine>.log`）：引擎的错误输出常常会指出缺失的文件。常见原因：程序被移动（*定位…*）、找不到网络或库（在其信息卡上设置工作目录或 `EvalFile`）、程序是为其他处理器构建的（在不支持 AVX-512 的机器上使用 AVX-512 构建版本）、启动缓慢（在其信息卡上增大*启动超时（秒）*）。见[无法启动的引擎](#无法启动的引擎)。
- **WinBoard 引擎无法从开局库的局面开始**。不支持 `setboard` 的协议 1 引擎只能从初始局面开始：请为它提供 PGN 开局库（着法），而不是 EPD 开局库。见 [WinBoard 引擎](#winboard-引擎)。
- **锦标赛拒绝开始：某个引擎不支持 Chess960**。每个引擎都必须有 `UCI_Chess960` 选项（UCI）或 `fischerandom` 变体（WinBoard）；摘要会指出不支持的引擎。

### 对局输掉或结果有误
<!-- en: games-are-lost-or-look-wrong f8a7cc97 -->

- **引擎在对局早期就超时判负**。这更常见于设置不当，而不是下得不好：线程数超过对局可用的核心数、哈希太大无法及时分配、每局都加载网络、启动缓慢。降低它的 `Threads` 和 `Hash`，取消勾选*每局对局都重启引擎*，增大*启动超时（秒）*；*稳定性*卡片和概览中的 *TF* 会显示超时判负。
- **引擎似乎比应有的速度慢**。同时进行的对局太多：让*并发*保持自动，并使并发数 × 线程数不超过物理核心数。概览中的*处理器占用*会指出占用的核心多于其 `Threads`、或在对手的时间里思考的引擎。
- **摘要警告内存不够**。对局的哈希表放不进空闲内存：降低 `Hash`（在*引擎设置*中，或在所指出的那个引擎上）或并发数。
- **提示残局库文件缺失或被截断**。下载中途停止了，或者文件夹中只有较小的残局库：重新下载工具提示中列出的文件，或者把裁定降到已找到的棋子数（*降为 5 子*）。
- **提示开局库中有非法局面或重复局面**。fastchess 会排除它们；开局库页面上的*保存清理后的副本…* 会写出一个不含它们的开局库。见[检查开局库](#检查开局库)。
- **某局对局判定错误**。在*对局*或*赛程*中右键点击它：重下、作废，或设定其结果并给出原因。见[修改进行中的锦标赛](#修改进行中的锦标赛)。

### 直播问题
<!-- en: broadcasting 4a2e6916 -->

- **TLCV 或其他查看器无法连接**。先开始锦标赛（及其 TLCS 服务器），再打开查看器：查看器不会自行重新登录。对于局域网以外的观众，请在路由器中开放 UDP 端口。
- **从外部无法访问网页**。勾选*发布到互联网*以使用隧道（见[把网页放到互联网上](#把网页放到互联网上)），或者在路由器中开放 TCP 端口。
- **lichess 拒绝令牌**。令牌需要 `study:write` 权限：用*在 lichess 上创建令牌…* 创建一个新令牌。在代理后面时，请设置 `HTTPS_PROXY`。

### 其他问题
<!-- en: anything-else ce59c083 -->

**设置**中或**日志**页面上的*报告问题…* 会打开一个 GitHub 问题，并已填入版本、系统和日志的最后几行（见[报告问题](#报告问题)）。

## 术语表
<!-- en: glossary 0386d0d9 -->

- **裁定（Adjudication）**：在结果已经明确时，于将杀之前结束对局：双方评分都保持在 0 附近时判和，一直远低于 0 时判负，或者按残局库给出的结果。见[裁定](#裁定)。
- **BayesElo、DrawElo**：一种为和棋单独设置参数（DrawElo）的等级分模型，出自 Rémi Coulom 的程序。
- **Berger 表（Berger tables）**：循环赛中各轮的编排顺序，使每个引擎每轮下一次。
- **Buchholz、Sonneborn-Berger**：破同分的方法：对手得分之和（瑞士制），以及所战胜对手的得分之和加上战和对手得分之和的一半（循环赛）。
- **Chess960、Chess324**：底线棋子随机排列的初始局面：960 种，王位于两车之间（易位后到达通常的格子）；324 种，王和车留在原位。
- **并发（Concurrency）**：同时进行的对局数。
- **循环（Cycle）**：在循环赛中，每组配对以每种颜色各下一次（cutechess 称之为 round，每次相遇 2 局）。
- **ECO**：《国际象棋开局百科全书》（Encyclopaedia of Chess Openings）的代码，A00 到 E99。
- **Elo、nElo**：一个得分所对应的等级分差。nElo（normalized Elo，归一化 Elo）除以结果的离散程度，因此其值不依赖于和棋率；fishtest 和 OpenBench 用它来表示 SPRT 边界。
- **EPD、FEN**：描述一个局面的一行文字；EPD 行可以带有操作，例如测试集的最佳着法 `bm`。
- **车轮战（Gauntlet）**：被测引擎（种子）与其他每个引擎对局，其他引擎之间不对局。
- **H0、H1**：SPRT 的两个假设：Elo 差不超过 elo0（H0），或者至少为 elo1（H1）。
- **Hash**：引擎用于置换表的内存，以 MB 计。
- **LLR**：SPRT 的对数似然比；当它超出由 alpha 和 beta 得出的边界时，测试结束。
- **LOS**：优势概率（likelihood of superiority），即根据对局结果，一个引擎强于另一个引擎的概率。
- **MultiPV**：引擎同时搜索多条变化。
- **开局集、开局库（Opening suite, book）**：对局开始时所用的局面或着法，每个都交换颜色下两次。
- **五项分布（Pentanomial）**：按总分统计对局对的结果：0、½、1、1½ 或 2 分。由于一对中的两局共用一个开局，它给出的误差范围比按单局统计更窄。
- **PGN**：国际象棋对局的文本格式：先是 `[White "…"]` 这样的标签，然后是着法。
- **Polyglot**：大多数程序都能读取的开局库二进制格式（`.bin`），每步着法带有一个权重。
- **Ponder**：在对手的时间里思考；在 fastchess-gui 的锦标赛中关闭。
- **种子（Seed）**：在参赛者顺序中的位置：车轮战的被测引擎、淘汰赛的热门选手。
- **SPRT**：序贯概率比检验（sequential probability ratio test），它不断进行对局，直到能以所选的错误率（alpha、beta）判断一个引擎是提升了至少 elo1（H1），还是提升不超过 elo0（H0）。
- **Syzygy**：给出每个少子局面结果的残局库（WDL 文件，`.rtbw`）。
- **TF**：超时判负（time forfeits），即因超时而输掉的对局。
- **线程（Threads）**：引擎搜索时使用的处理器线程。
- **TLCS、TLCV**：Tom's Live Chess Server 和 Viewer，一种实时跟踪引擎对局的协议。
- **UCI、WinBoard（CECP）**：程序与国际象棋引擎通信所用的两种协议。
- **WDL**：引擎随评分一起给出的胜、和、负概率。
