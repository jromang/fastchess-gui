Features for engine testers, many of them seen in Myracle and TorsGUI (#86 to #109): opponents picked by rating,
a rating list import, a gauntlet table for forum posts, an export and a checklist for rating list submissions,
resume at launch, arrows on the live board, one TLCS port per game, a richer web page and a command palette.

## Engines

- Notes on each engine, found by every engine search (#107).
- The folder of *Every engine of a folder…* is remembered; *Refresh: the new engines of the folder* offers only
  the engines not yet in the library (#106).
- Inactive engines: kept in the library, greyed, left out of the engine pickers and of *Check those not checked*
  (#106).
- *A rating list, for the reference Elo…* fills the reference Elo from a rating list's text or web page, Ordo's
  output or a CSV file, with a preview before anything is set (#91).
- A start timeout per engine, for engines that load a large network or hash table (#98).

## New tournament

- *Add an engine…* shows each engine's reference Elo and whether it works, sorts and filters by rating, and
  *Suggest N opponents within ±150 Elo* of the first participant (#92).
- The summary gives the memory the hash tables can take: a warning above the free memory, no start above the
  installed memory (#93).
- *Syzygy tablebases for the engines* and *Engines' own books off* for every engine that has those options
  (#94).
- Number fields accept arithmetic (`40*60`, `15+10`); Ctrl+Up / Ctrl+Down move a participant to the top or the
  bottom (#108).

## Running a tournament

- The tournament that was running when the program ended (a crash, a power cut, a reboot) resumes at the next
  launch, and the queue goes on. A tournament paused or stopped waits; a resume that ended the program is not tried
  again by itself (#95).
- The home page says when the tournament and the queue should end, and a *Health* card shows the crashes, losses
  on time and illegal moves of the last 24 hours, the free memory and the engine processes (#96).
- Live: arrows for the move the side to move thinks of and the reply it expects (#100); in a gauntlet, each new
  game shown from the tested engine's side (#99); a badge with the number of games in progress (#108).

## Results

- In a gauntlet, *Copy* offers the gauntlet table for forum posts, as text or BBCode (#89).
- Standings ordered by points, score or seed order, with a line under the copies giving the games, draws, time
  control, book and event (#101).
- A click on an engine lists its opponents with the games played with White and with Black; a pair with one game
  only is marked (#102).
- *Export for a rating list…* writes the games as rating list testers send them: the file named after the tester,
  the date and the conditions, the players as the lists write them, rounds renumbered, voided and duplicated games
  left out, optionally zipped (#88).
- A finished tournament's overview shows a submission checklist: all games played, colour pairs complete, no
  duplicates, crashes, time losses and illegal moves, hash, ponder, book, tablebases (#90).

## Broadcast

- TLCS: *One port per game* serves every concurrent game on its own UDP port (#103).
- The web page follows one game with an evaluation bar, arrows and charts, shows the statistics and anomalies, and
  offers the games' PGN file for download (#104).
- lichess still shows only its own evaluation: its source drops the engines' `[%eval]` (#105, see #69).

## Fixes

- The PlyCount of a game lost by an illegal move counts only the moves written (#86).
- Lines starting with `%` in a PGN book (escape lines, as in the AVT books) are ignored. Earlier versions read them
  as moves, so some openings were played from a wrong position; the Books page shows how many a book has (#87).

## Interface

- Ctrl+K opens a command palette: pages, tabs, engines, books, tournaments and the actions possible now (#109).
- A `?` beside each page title, or F1, opens the guide at the page's section (#109).
