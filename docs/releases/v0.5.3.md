Resume starts at once, and a start shows what it waits for.

## Fixes

- Resume no longer waits for an engine of the library being read at launch, and no longer seems to need two
  presses: a tournament plays the engines copied in its folder, so it starts at once.
- Start, the queue and the quick test wait only for the read of an engine they play. Any other read or check is
  interrupted, also for an engine behind a wrapper script or the WinBoard adapter, and done again later.
- A start that waits says so on its button (*Waiting for …*, with *Cancel*) and on the tournament's card; pressing
  again changes nothing, and another start is refused until it is cancelled.
- The queue goes one tournament at a time: a tournament whose engine cannot be read is skipped and stays in the
  queue, and the next one starts.
- A tournament started while a test suite runs waits for the suite, and a test suite does not start while a
  tournament runs or waits to start.
