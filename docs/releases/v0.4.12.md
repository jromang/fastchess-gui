Twelve known limitations lifted (#55 to #66): files that stay clean after a crash, engine logs with the error
output, engines kept running between games again, a lichess proxy, and the standings and statistics.

## Fixes

### Tournament files (#57, #58)

- **A crash or a power cut while games are appended to the file of *Also append every game to* no longer writes
  them twice there.** The resume checks the file, completes a write cut short, and never removes anything from it.
- **`games.pgn` and `games-chessbase.pgn` no longer hold games the tournament does not know.** A game dropped by a
  change while it was being saved, or game text left by a crash, is replaced with blank lines (at once, or when the
  tournament is resumed), so other PGN viewers only show the tournament's games. Matches imported from 0.2.x keep
  their files as they are.
- A write to the file of *Also append every game to* that fails partway (disk full) is completed by the next one,
  instead of leaving a cut-off game before the next game.
- Earlier versions can still open these tournaments.

### Engines (#59, #60, #61)

- **The engine logs hold what the engines write on their error output** (assertions, crash messages), marked
  `W!` / `B!` beside `W>` (sent to the engine) and `W<` (read from it). On Windows the error output is no longer
  mixed with the engine's output. What an engine writes there just before it crashes is read in full before
  its end is reported, and the lines written just before a game's last move go to that game's log.
- **Engines are kept running between games again.** 0.4.11 kept 4 waiting processes per game played at once, which
  restarted engines all the time in a round robin at concurrency 1. A tournament now keeps one waiting process per
  engine that still has games to play, up to 32 (plus two per game being played): a round robin of up to 32
  engines starts each engine once. Engines with no game left (gauntlet opponents once they have played, withdrawn
  or replaced participants) are closed after their last game.
- **A pause no longer gives up a game whose engine failed to start.** The next try comes after the resume, and the
  pause uses up none of the three tries. *Finish the running games, then stop* still gives such a game up at once.

### Standings and statistics (#55, #62, #64, #65)

- **The standings copied as text or BBCode, the HTML export** (and the broadcast's `standings.html`) **and the
  headless mode have the TF column** (losses on time), as the standings view does.
- **The processor use of the engines is kept when a tournament is resumed.** What each game's engines used is
  written with the game to `processor.tsv` in the tournament folder. Games played headless, or with earlier
  versions, have no measure.
- The search totals of the statistics count each game once, even when a game ends while a change makes a big
  tournament's games be read again.
- **Ratings: a player of an imported PGN file is taken for a library engine when it has the engine's name**,
  letter case and spaces aside ("stockfish  17" is "Stockfish 17"), and only when one library engine has that name.
  Its games count as the engine's, and the engine's reference Elo can anchor them. A name with anything more
  ("Stockfish 17 64-bit") stays a separate engine. The rating list says how many library engines the PGN files
  hold, and its tooltip lists them.

### lichess (#56, #66)

- **The lichess connection goes through an HTTP proxy**: the one `HTTPS_PROXY` (or `ALL_PROXY`) names, for
  example `http://proxy.example:3128` or `http://user:password@proxy.example:3128`. Hosts listed in `NO_PROXY` are
  reached directly. Only `http://` proxies are supported (no SOCKS); on Windows too, the proxy comes from these
  variables, not from the system settings.
- The API token is saved when its field is left, or when the program quits, no longer at every key.

### Interface (#63)

- Ctrl + mouse wheel only changes the size of the interface: the chart under the mouse no longer zooms as well,
  Shift or Alt held or not.

## Known limitations

- `games.pgn` and `games-chessbase.pgn` stay in the order games end: the tournament finds each game by its place
  there. The file of *Also append every game to* is the one in schedule order. Blanked games show as blank lines.
- A lichess round holds 64 games; the next ones go to a new round of the same broadcast. lichess keeps only the
  moves and clocks of a broadcast: the engines' evaluations do not show there.
- The lichess connection trusts only Google Trust Services and Let's Encrypt; proxies need no authentication or
  Basic authentication (no NTLM, Kerberos).
- Charts of the replay need their fields in the PGN (nodes, seldepth, nps, pv, tbhits, decision time are PGN
  options of the setup); the live view always has them.
- WinBoard engines of protocol 1 without `setboard` nor edit mode can only start from the initial position.
- The TLCS server has been tried with node-tlcv, not with Tom's Live Chess Viewer itself.
- On Wayland, detached boards stay inside the main window.
- Windows before 10 version 1903 is not tested: paths with accents may fail there (#46).
