A macOS version, opening books that can no longer crash a tournament, and the code now checked automatically for
vulnerabilities.

## macOS

- fastchess-gui and the fastchess command line tool now run on macOS 13.3 (Ventura) or newer, Apple silicon and
  Intel, as one universal application. The profile is in `~/Library/Application Support/fastchess/fastchess-gui/`;
  CPU affinity, which macOS does not have, is not offered there. Headless:
  `fastchess-gui.app/Contents/MacOS/fastchess-gui --run …`.
- The application is not signed by an Apple developer account, so macOS refuses it the first time: Control-click
  (right-click) it, choose Open, then Open again. On macOS 15 and later, try to open it once, then go to System
  Settings, Privacy & Security, and click Open Anyway. Or, in Terminal, run `xattr -dr com.apple.quarantine` on the
  unzipped folder, which also clears the fastchess tool next to it. Engines you download yourself may need the same.
- It is built and its tests run on GitHub's Macs; it has not been tried by a person on a Mac yet. Reports are welcome.

## Opening books and test suites

- An opening book could crash a tournament: a PGN game with a comment before its first move, a FEN tag or EPD line
  without a king or otherwise malformed, or a malformed castling move. Openings whose position cannot be played are
  now left out with a warning (one line per book); on the *Books* page they count as illegal positions.
- An ambiguous move in a PGN book now ends that opening's line instead of rejecting the whole book.
- An EPD test suite, an opening book under inspection, a PGN book turned into an engine's own book, or a WinBoard
  engine's move can no longer crash the program with such positions or moves; they are skipped or flagged as
  illegal.

## Safety

- A tournament folder received from someone else can no longer make the program write outside it: the file every
  game is also appended to must be a `.pgn` file (older tournaments with another name open with a warning and no
  longer append there), and a folder whose journal, PGN files or lock file are symbolic links is not opened for
  writing.
- Files the program creates are not writable by other users whatever the umask, and `settings.json` is readable by
  its owner only from the moment it holds a lichess token.
- The code, the vendored fastchess included, is now checked automatically: CodeQL on every change, Coverity Scan
  every week, the tests under AddressSanitizer and UndefinedBehaviorSanitizer, the dependencies against known
  vulnerabilities (OSV-Scanner, from a list of every dependency in `sbom/fastchess-gui.cdx.json`), and fuzzers
  feeding malformed web requests, tunnel server text, TLCS datagrams, PGN and EPD files and engine output to the
  program.

## Broadcast tunnel

- The tunnel's memory stays bounded whatever its viewers send: it reads every viewer's connection on every pass,
  waiting ones included, and a viewer sending a flood of tiny packets, or all of them sending at once while your
  connection is saturated, no longer ends the session; such a viewer is let go alone. Viewers beyond its capacity
  (40 relayed, 40 waiting, 40 queued by the SSH library) are refused at once.
- The bundled libssh2 is modified for this (see `cmake/patch_libssh2.cmake`): a viewer's connection holds at most
  128 KiB, and a channel's small packets are kept as bytes rather than a block of memory each.
- The tunnel no longer leaves its SSH session (its memory and keys) behind when a connection ends while the server
  has stopped reading, and its goodbye reaches the server though a packet was left half sent.

## Engines

- On macOS and Linux, an engine started by a wrapper script is ended with the script when a check or a game is
  interrupted.
