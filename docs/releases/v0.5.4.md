An opening book of its own for each participant, and Arena's engine list.

## Participants

- Each participant can have its own Polyglot book (`.bin`) from the Books page and a depth in plies, like Cute
  Chess' `book=`/`bookdepth=`: the *Book* cell of the participants list (next to A and B in a match). While the
  game is in that book, within the depth (counted from the start, the tournament's opening included), its moves are
  played at once, drawn by the book's weights; then the engine plays.
- The same engine can play several times with different books: *This engine once more, with another book* adds a
  copy, named "Stockfish 19 (Book A)", "Stockfish 19 (Book B)" in the PGN, the standings and the ratings. In a
  match, an engine can play itself with two books.
- Book moves are marked `{book}` in the PGN. WinBoard engines can have a book too. fastchess itself is unchanged:
  fastchess-gui plays the book in front of the engine.
- Book moves are drawn anew for every game, so they are not reproducible, even with the tournament seed set.
- A Polyglot book whose entries are not sorted is sorted in memory up to 16 MB; a larger one is refused, with the
  reason.
- A tournament with an own book is refused by versions up to 0.5.3, which would play the engines without their
  books.

## Engines

- *Import* > *An engine list…* reads Arena's engine list (`ArenaENG.cfg`, in Arena's folder): each engine's program,
  arguments, protocol and, for UCI engines, the option values set in Arena. Engines whose program is no longer there
  are left out, with a note.
- An import that finds no engine says so, lists the formats it reads, and offers *Every engine of a folder…* on the
  list's folder; when every engine found is already in the library, it says that too.
- What an engine writes right after its move, in the same write, is no longer lost through the WinBoard adapter.
