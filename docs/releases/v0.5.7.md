The broadcast web page points to where its viewers talk: a chat link and a Discord tab.

## Broadcast

- A *Chat link* under *Web page* in the *Broadcast* tab (a Discord invite, a Twitch channel, a forum thread; https
  only) puts a *Chat* button in the page's header that opens it in a new tab. While the games are pushed to lichess,
  the page also links to the lichess round, which has its own chat.
- A *Discord server ID* adds a *Discord* tab beside *Event*, with Discord's server widget in the page's light or dark
  theme: the server's name, the members online, its voice channels and a *Join* button, not the messages. The server's
  owner switches the widget on in Discord's Server Settings, Widget, which also shows the server ID. The widget is
  loaded from discord.com only once a viewer opens the tab, so Discord learns of no one else's visit.
- Headless runs take both from the setup file (`web_chat_link`, `web_discord_id`). Without them, the page is as before.
- When the tunnel stops, the server now gets its goodbye: on Windows the connection could end in a reset instead,
  while the server was still sending.

## Downloads

| `fastchess-gui-v0.5.7-linux-x86_64.tar.gz` | `fastchess-gui` and the `fastchess` command line tool, x86-64 Linux (glibc 2.35 or newer). Needs X11 or Wayland and OpenGL 3.2. |

The binaries are built by this repository's GitHub Actions workflow; the tests run on Linux and on Windows. The
archives carry the licenses of the libraries built in (see `ATTRIBUTION.md`).
