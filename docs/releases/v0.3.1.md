Broadcasting fixes found by watching a live tournament, and broadcasting from headless mode.

## Changes

- **TLCS** now speaks the protocol Tom's Live Chess Viewer 2.1 expects (checked against node-tlcv's notes on the
  official client, and a live tournament watched by a client that behaves like it):
  - `LOGON SUCCESSFUL` after a logon: TLCV ignored everything else without it, so it showed nothing;
  - `FEATURE: PING`, without which TLCV never sends its keepalive, and acknowledgement of the client's numbered
    messages (its `PING`);
  - clocks as `WTIME: <cs> otim <cs>`, the form TLCV requires;
  - the FEN sent before a move is the position after it, as TLCS does: TLCV drew the board one move late;
  - mate scores as node-tlcv reads them (it showed mate in 2N instead of N);
  - the end of the game followed (its last move and result) is always sent: it was lost when the next game
    started in the same slot before the broadcast saw the end, which was nearly always the case.
- **Headless mode broadcasts**: `fastchess-gui --run FOLDER --tlcs 16001 --web 8080 --live-files`, or the
  broadcast settings of a setup file.
- In the light theme, text fields, check boxes and radio buttons show on the white cards.

## Known limitations

- The TLCS server has been checked against node-tlcv's documentation and source and a client written from it,
  not yet against TLCV itself or a running node-tlcv.
- Only the last change of a tournament can be undone, and only until the next game starts.
- On Wayland, detached boards stay inside the main window.
- No Chess960 option in the interface.
