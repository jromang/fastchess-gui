The broadcast web page redone and put on the internet from the program, a richer rating list, and several known limitations lifted.

## Broadcast

- The web page centres on the followed game: large clocks, each engine's evaluation in large type with who is
  thinking, its search as tiles (depth, nodes, speed, time, tablebase hits, hash) and its line of play, the last
  move, a king in check and the coordinates on the board, and the moves with the book moves told apart.
- On the web page, step through the moves of the followed game (buttons or arrow keys, back to live at the end),
  turn the board, and copy the game's PGN or the position's FEN.
- The page is denser: board, engines and moves together, with the standings and crosstable, the charts, each
  engine's search on average, the next games of the schedule, the statistics and the event in tabs; one column on
  phones. Moves in letters or figurines, a light/dark switch beside the automatic theme, and a small evaluation bar
  beside each player of every game in progress.
- The web server answers each request on its own, with limits, so a slow visitor holds no one else; it answers only
  GET for its own paths. The page and its state are sent compressed, the state at about a quarter of its size.
- *Publish on the internet* under *Web page* puts the page on the internet from fastchess-gui itself, with nothing to
  install: an SSH tunnel built into the program (libssh2, on the cryptography the program already ships) to
  localhost.run, free and without an account, or to another SSH server. The public https address is shown with
  *Copy*, *Open* and a QR code for a phone; the tunnel reconnects by itself and stops with the tournament.
  localhost.run's host key is checked against the one it is known to have; another server's is trusted the first
  time and must stay the same. It relays 40 viewer connections at once with 40 more waiting, and a viewer who sends
  more than the page takes is let go alone. Headless: `--tunnel [localhost.run|ssh://user@host[:port][/remote_port]]`.
- `state.json` gains each engine's search on average, the next games, the moves in UCI and SAN, the book moves, each
  search's selective depth, speed, tablebase hits and hash, the time control and whether the games are Chess960.

## Ratings

- The rating list shows wins, draws and losses, the draw rate, the average rating of the opponents, and the LOS and
  Elo gap over the next engine. It sorts by any column, and columns can be hidden from the header's right-click menu.
  The copies and the CSV export carry the new columns.
- The rating list exports as an HTML page (light and dark) and as Markdown, each with a header that tells the
  sources, the games and results, the anchor, the filters, the date and the version. The same header can top the
  text and BBCode copies.
- A player of an imported PGN file whose name is not exactly a library engine's can be assigned to one in the new
  *PGN players* window. A name two library engines share is shown there to choose instead of being dropped, a likely
  engine is suggested as a hint (never applied by itself), and a player can be kept as a separate engine. The choices
  are kept with the engine and apply to every PGN file and to the rating lists imported for the reference Elo.

## Games and logs

- The PGN fields the charts of the *Games* tab read (nodes, seldepth, nps, pv, tbhits, decision time) are now on by
  default, so the replay draws every chart for the tournaments played from now on. A saved setup with all of them
  off, the old default, gets them on. When a game's PGN lacks a field, the replay names the setup option that writes
  it, with a button to the PGN options.
- Each engine keeps its own first 300 lines in a game's engine log, so a chatty engine no longer pushes the other's
  start out of it.
- Games played headless (`--run`) record their processor use too, and each line of `processor.tsv` is synced to the
  disk.

## Engines

- A game waiting to try again an engine that failed to start no longer shows as running while the tournament is
  paused.
- A game given up while its engine failed to start no longer leaves that engine's dead process behind, whose next
  game was lost at once.
- In a knockout, a player's waiting engine process ends as soon as its match is lost; in a Swiss, once it has no game
  left in the last round.
